## 📖 常见面试题

### 1. Docker 相关

**Q1: 容器和虚拟机的区别是什么？**

```
虚拟机：
- 完整 Guest OS（几百 MB 到几 GB）
- Hypervisor 虚拟化硬件
- 启动 1-3 分钟
- 强隔离（独立内核）

容器：
- 共享宿主内核
- 进程级隔离（namespace + cgroup）
- 启动毫秒级
- 轻量（MB 级）
```

**Q2: Docker 镜像分层原理是什么？**

```
镜像由多个只读层（layer）叠加而成
每层对应 Dockerfile 的一条指令（RUN/COPY/ADD）
优势：
- 层缓存：修改后面的层，前面的层不重建
- 共享：多个镜像共享相同基础层
- 增量拉取：只下载缺失的层

Container 层：最上面的可写层（读写操作在这里）
```

**Q3: Docker 网络模式有哪些？**

```
bridge: 默认，容器通过网桥连接，NAT 到宿主机
host: 容器共享宿主机网络栈
none: 无网络
overlay: 跨主机网络（Swarm/K8s）
macvlan: 给容器分配真实 MAC 地址
```

### 2. Kubernetes 相关

**Q4: Pod 是什么？为什么 K8s 不直接调度容器？**

```
Pod 是 K8s 最小调度单元，包含一个或多个容器
共享：网络（同一 IP）、存储（Volume）、IPC

为什么不只调度容器：
- 需要 sidecar 模式（日志收集、代理）
- 需要多个容器协同工作（主容器 + 辅助容器）
- 网络共享：容器间用 localhost 通信
```

**Q5: Deployment 滚动更新原理？**

```
假设 replicas=3, maxSurge=1, maxUnavailable=1

Step 1: 创建 1 个新 Pod → 4 个运行（3 旧 + 1 新）
Step 2: 新 Pod 就绪后，终止 1 个旧 Pod → 3 个运行（2 旧 + 1 新）
Step 3: 重复直到所有 Pod 都是新版本

回滚：kubectl rollout undo deployment/xxx
```

**Q6: Pod 启动失败，如何排查？**

```
1. kubectl get pods → 查看状态（Pending/CrashLoopBackOff/ImagePullBackOff）
2. kubectl describe pod <name> → 查看 Events
3. kubectl logs <name> → 查看容器日志
4. 常见问题：
   - ImagePullBackOff: 镜像不存在/权限不足
   - CrashLoopBackOff: 应用启动失败/配置错误
   - Pending: 资源不足/调度失败
   - OOMKilled: 内存超限
```

**Q7: Service 的类型有哪些？区别是什么？**

```
ClusterIP: 集群内部访问（默认）
NodePort: 通过节点端口暴露（30000-32767）
LoadBalancer: 云厂商负载均衡器
ExternalName: CNAME 到外部服务
```

**Q8: 如何限制 Pod 资源使用？**

```yaml
resources:
  requests:
    cpu: "100m"      # 保证 0.1 CPU
    memory: "128Mi"  # 保证 128MB
  limits:
    cpu: "500m"      # 最多 0.5 CPU
    memory: "256Mi"  # 最多 256MB，超限 OOMKill
```
