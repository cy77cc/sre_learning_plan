## 📖 核心知识点

### 1. 容量规划概述

#### 1.1 什么是容量规划

容量规划（Capacity Planning）是确保系统有足够的资源来满足当前和未来需求的过程。Google SRE Book 第 34 章指出：

> "Capacity planning is the process of determining the resources needed to meet the anticipated demand for a service."

```
┌─────────────────────────────────────────────────────────┐
│                 容量规划的核心目标                         │
│                                                         │
│  1. 满足性能需求                                         │
│     • 响应时间在 SLO 范围内                              │
│     • 吞吐量能满足业务峰值                              │
│     • 资源利用率在合理范围                               │
│                                                         │
│  2. 控制成本                                             │
│     • 避免过度配置（浪费）                               │
│     • 避免配置不足（影响业务）                           │
│     • 优化资源使用效率                                   │
│                                                         │
│  3. 支持业务增长                                         │
│     • 提前规划资源扩展                                   │
│     • 预测未来需求                                       │
│     • 制定扩容策略                                       │
└─────────────────────────────────────────────────────────┘
```

#### 1.2 容量规划的类型

```
┌─────────────────────────────────────────────────────────┐

│                                                         │
│  1. 短期规划（1-3 个月）                                 │

│                                                         │
│  2. 中期规划（3-12 个月）                                │

│     • 技术架构升级                                       │
│                                                         │
│  3. 长期规划（1-3 年）                                   │

```

### 2. 需求预测方法

#### 2.1 趋势分析

趋势分析是最基本的需求预测方法，基于历史数据预测未来：

```
┌─────────────────────────────────────────────────────────┐
│                  趋势分析方法                             │
│                                                         │
│  线性趋势：                                              │
│  ┌───────────────────────────────────────┐              │
│  │ y = a + b*t                           │              │
│  │                                       │              │
│  │ t: 时间                               │              │
│  │ a: 截距（初始值）                      │              │
│  │ b: 斜率（增长率）                      │              │
│  │                                       │              │
│  │ 适用：稳定增长的业务                   │              │
│  └───────────────────────────────────────┘              │
│                                                         │
│  指数趋势：                                              │
│  ┌───────────────────────────────────────┐              │
│  │ y = a * e^(b*t)                       │              │
│  │                                       │              │
│  │ 适用：快速增长的业务                   │              │
│  └───────────────────────────────────────┘              │
│                                                         │
│  移动平均：                                              │
│  ┌───────────────────────────────────────┐              │
│  │ MA(t) = (y(t) + y(t-1) + ... + y(t-n)) / n         │
│  │                                       │              │
│  │ 适用：平滑短期波动                     │              │
│  └───────────────────────────────────────┘              │
└─────────────────────────────────────────────────────────┘
```

#### 2.2 季节性分析

许多业务有明显的季节性特征：

```python
# capacity_forecast.py
import numpy as np
from datetime import datetime, timedelta

class CapacityForecaster:
    def __init__(self, historical_data):
        """
        historical_data: dict of {date: metric_value}
        """
        self.data = historical_data
        self.dates = sorted(historical_data.keys())
        self.values = [historical_data[d] for d in self.dates]
    
    def linear_trend(self, days_ahead):
        """线性趋势预测"""
        n = len(self.values)
        x = np.arange(n)
        y = np.array(self.values)
        
        # 最小二乘法拟合
        b = (n * np.sum(x * y) - np.sum(x) * np.sum(y)) / \
            (n * np.sum(x**2) - np.sum(x)**2)
        a = np.mean(y) - b * np.mean(x)
        
        # 预测
        future_x = n + days_ahead
        prediction = a + b * future_x
        
        return {
            'prediction': prediction,
            'trend_slope': b,
            'current_value': y[-1],
            'growth_rate': b / y[-1] * 100
        }
    
    def seasonal_factor(self, target_month):
        """计算季节性因子"""
        monthly_avg = {}
        for date, value in self.data.items():
            month = date.month
            if month not in monthly_avg:
                monthly_avg[month] = []
            monthly_avg[month].append(value)
        
        overall_avg = np.mean(self.values)
        monthly_factors = {}
        for month, values in monthly_avg.items():
            monthly_factors[month] = np.mean(values) / overall_avg
        
        return monthly_factors.get(target_month, 1.0)
    
    def forecast_with_seasonality(self, target_date):
        """带季节性因子的预测"""
        # 基础趋势预测
        days_ahead = (target_date - self.dates[-1]).days
        trend = self.linear_trend(days_ahead)
        
        # 季节性调整
        seasonal = self.seasonal_factor(target_date.month)
        
        return {
            'base_prediction': trend['prediction'],
            'seasonal_factor': seasonal,
            'adjusted_prediction': trend['prediction'] * seasonal,
            'confidence_range': {
                'low': trend['prediction'] * seasonal * 0.8,
                'high': trend['prediction'] * seasonal * 1.2
            }
        }

# 使用示例
# 假设我们有 12 个月的 QPS 数据
monthly_qps = {
    datetime(2025, 1, 1): 1000,
    datetime(2025, 2, 1): 1100,
    datetime(2025, 3, 1): 1200,
    datetime(2025, 4, 1): 1150,
    datetime(2025, 5, 1): 1300,
    datetime(2025, 6, 1): 1400,
    datetime(2025, 7, 1): 1500,
    datetime(2025, 8, 1): 1450,
    datetime(2025, 9, 1): 1600,
    datetime(2025, 10, 1): 1700,
    datetime(2025, 11, 1): 2000,  # 双十一
    datetime(2025, 12, 1): 1800,
}

forecaster = CapacityForecaster(monthly_qps)

# 预测下个月（2026年1月）
target = datetime(2026, 1, 1)
result = forecaster.forecast_with_seasonality(target)

print(f"=== 容量预测报告 ===")
print(f"当前 QPS: {monthly_qps[datetime(2025, 12, 1)]}")
print(f"趋势增长率: {result['base_prediction']:.0f}")
print(f"季节性因子: {result['seasonal_factor']:.2f}")
print(f"预测 QPS: {result['adjusted_prediction']:.0f}")
print(f"置信区间: {result['confidence_range']['low']:.0f} - {result['confidence_range']['high']:.0f}")
```

### 3. 性能建模

#### 3.1 排队论基础

排队论是性能建模的理论基础：

```
┌─────────────────────────────────────────────────────────┐
│                  排队论基础                               │
│                                                         │
│  M/M/1 模型（单服务台）：                                │
│  ┌───────────────────────────────────────┐              │
│  │ 到达率: λ (请求/秒)                    │              │
│  │ 服务率: μ (请求/秒)                    │              │
│  │ 利用率: ρ = λ / μ                      │              │
│  │                                       │              │
│  │ 平均响应时间: T = 1 / (μ - λ)         │              │
│  │ 平均排队长度: L = ρ / (1 - ρ)         │              │
│  │                                       │              │
│  │ 当 ρ → 1 时，响应时间趋于无穷大        │              │
│  │ 推荐: ρ < 0.7 (留 30% 余量)           │              │
│  └───────────────────────────────────────┘              │
│                                                         │
│  M/M/c 模型（多服务台）：                                │
│  ┌───────────────────────────────────────┐              │
│  │ c 个并行服务台                         │              │
│  │ 总服务率: c × μ                        │              │
│  │                                       │              │
│  │ 适用：多实例部署、连接池               │              │
│  └───────────────────────────────────────┘              │
└─────────────────────────────────────────────────────────┘
```

#### 3.2 资源估算模型

```python
# resource_estimation.py

class ResourceEstimator:
    def __init__(self):
        self.services = {}
    
    def add_service(self, name, config):
        """
        config: {
            'qps': 预期 QPS,
            'cpu_per_request': 每请求 CPU 核数,
            'memory_per_request': 每请求内存 (MB),
            'target_cpu_utilization': 目标 CPU 利用率,
            'target_memory_utilization': 目标内存利用率,
        }
        """
        self.services[name] = config
    
    def estimate(self, name, peak_factor=3, safety_factor=1.3):
        """估算所需资源"""
        config = self.services[name]
        
        peak_qps = config['qps'] * peak_factor
        safe_qps = peak_qps * safety_factor
        
        # CPU 估算
        cpu_needed = safe_qps * config['cpu_per_request']
        target_cpu = config['target_cpu_utilization']
        total_cpu = cpu_needed / target_cpu
        
        # 内存估算
        memory_needed = safe_qps * config['memory_per_request']
        target_memory = config['target_memory_utilization']
        total_memory = memory_needed / target_memory
        
        # 实例数估算（假设每实例 2 核 4GB）
        cpu_per_instance = 2
        memory_per_instance = 4096  # MB
        
        instances_by_cpu = total_cpu / cpu_per_instance
        instances_by_memory = total_memory / memory_per_instance
        instances_needed = max(instances_by_cpu, instances_by_memory)
        
        return {
            'service': name,
            'base_qps': config['qps'],
            'peak_qps': peak_qps,
            'safe_qps': safe_qps,
            'cpu_cores': round(total_cpu, 2),
            'memory_mb': round(total_memory, 2),
            'instances_needed': int(np.ceil(instances_needed)),
            'cpu_per_instance': cpu_per_instance,
            'memory_per_instance': memory_per_instance
        }

# 使用示例
estimator = ResourceEstimator()

# 添加服务配置
estimator.add_service('user-service', {
    'qps': 1000,
    'cpu_per_request': 0.001,  # 每请求 1ms CPU 时间
    'memory_per_request': 0.5,  # 每请求 0.5MB
    'target_cpu_utilization': 0.6,
    'target_memory_utilization': 0.7
})

estimator.add_service('order-service', {
    'qps': 500,
    'cpu_per_request': 0.002,  # 更复杂，每请求 2ms
    'memory_per_request': 1.0,
    'target_cpu_utilization': 0.6,
    'target_memory_utilization': 0.7
})

# 估算资源
for service_name in ['user-service', 'order-service']:
    result = estimator.estimate(service_name)
    print(f"\n=== {service_name} 资源估算 ===")
    print(f"基础 QPS: {result['base_qps']}")
    print(f"峰值 QPS: {result['peak_qps']}")
    print(f"安全 QPS: {result['safe_qps']}")
    print(f"所需 CPU: {result['cpu_cores']} 核")
    print(f"所需内存: {result['memory_mb']} MB")
    print(f"所需实例: {result['instances_needed']} 个")
```

### 5. 弹性伸缩策略

#### 5.1 HPA（Horizontal Pod Autoscaler）

```
┌─────────────────────────────────────────────────────────┐
│                    HPA 工作原理                           │
│                                                         │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐          │
│  │ Metrics  │    │  HPA     │    │ Deployment│          │
│  │ Server   │──→│ Controller│──→│ Replica  │          │
│  │          │    │          │    │ Count    │          │
│  └──────────┘    └──────────┘    └──────────┘          │
│       │               │               │                │
│       │               │               │                │
│       ▼               ▼               ▼                │
│  收集 Pod 指标    计算所需副本数   调整 Pod 数量         │
│  (CPU/内存/自定义)                                      │
│                                                         │
│  计算公式：                                              │
│  期望副本数 = ceil(当前副本数 × (当前指标 / 目标指标))   │
│                                                         │
│  例：当前 5 个 Pod，CPU 使用率 80%，目标 50%            │
│  期望副本数 = ceil(5 × (80/50)) = ceil(8) = 8          │
└─────────────────────────────────────────────────────────┘
```

```yaml
# HPA 配置示例
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: user-service-hpa
  namespace: production
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: user-service
  minReplicas: 3
  maxReplicas: 50
  metrics:
    # CPU 基础扩缩容
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 60
    
    # 内存扩缩容
    - type: Resource
      resource:
        name: memory
        target:
          type: Utilization
          averageUtilization: 70
    
    # 自定义指标：QPS
    - type: Pods
      pods:
        metric:
          name: http_requests_per_second
        target:
          type: AverageValue
          averageValue: "1000"
  
  behavior:
    scaleUp:
      stabilizationWindowSeconds: 60
      policies:
        - type: Percent
          value: 100
          periodSeconds: 60
    scaleDown:
      stabilizationWindowSeconds: 300
      policies:
        - type: Percent
          value: 10
          periodSeconds: 60
```

#### 6.2 数据库容量计算

```python
# database_capacity.py

class DatabaseCapacityPlanner:
    def __init__(self, db_type='mysql'):
        self.db_type = db_type
    
    def estimate_storage(self, config):
        """估算存储需求"""
        current_size_gb = config['current_size_gb']
        daily_growth_gb = config['daily_growth_gb']
        retention_days = config['retention_days']
        index_ratio = config.get('index_ratio', 0.3)
        safety_factor = config.get('safety_factor', 1.5)
        
        # 基础数据量
        base_storage = current_size_gb + (daily_growth_gb * retention_days)
        
        # 加上索引
        with_index = base_storage * (1 + index_ratio)
        
        # 加上安全余量
        total = with_index * safety_factor
        
        return {
            'current_size_gb': current_size_gb,
            'projected_size_gb': base_storage,
            'with_index_gb': with_index,
            'recommended_gb': total,
            'daily_growth_gb': daily_growth_gb
        }
    
    def estimate_iops(self, config):
        """估算 IOPS 需求"""
        read_qps = config['read_qps']
        write_qps = config['write_qps']
        read_io_per_query = config.get('read_io_per_query', 2)
        write_io_per_query = config.get('write_io_per_query', 3)
        
        read_iops = read_qps * read_io_per_query
        write_iops = write_qps * write_io_per_query
        total_iops = read_iops + write_iops
        
        return {
            'read_iops': read_iops,
            'write_iops': write_iops,
            'total_iops': total_iops,
            'recommended_iops': total_iops * 1.3  # 30% 余量
        }
    
    def estimate_connections(self, config):
        """估算连接数需求"""
        app_instances = config['app_instances']
        pool_size = config.get('pool_size', 20)
        max_connections = app_instances * pool_size
        
        return {
            'app_instances': app_instances,
            'pool_size': pool_size,
            'total_connections': max_connections,
            'recommended_max': int(max_connections * 1.2)
        }

# 使用示例
planner = DatabaseCapacityPlanner('mysql')

# 存储估算
storage = planner.estimate_storage({
    'current_size_gb': 500,
    'daily_growth_gb': 5,
    'retention_days': 365,
    'index_ratio': 0.3,
    'safety_factor': 1.5
})

print("=== 存储容量规划 ===")
print(f"当前数据量: {storage['current_size_gb']} GB")
print(f"预计增长: {storage['daily_growth_gb']} GB/天")
print(f"1年后数据量: {storage['projected_size_gb']:.0f} GB")
print(f"含索引: {storage['with_index_gb']:.0f} GB")
print(f"推荐存储: {storage['recommended_gb']:.0f} GB")

# IOPS 估算
iops = planner.estimate_iops({
    'read_qps': 5000,
    'write_qps': 1000,
    'read_io_per_query': 2,
    'write_io_per_query': 3
})

print("\n=== IOPS 规划 ===")
print(f"读 IOPS: {iops['read_iops']}")
print(f"写 IOPS: {iops['write_iops']}")
print(f"总 IOPS: {iops['total_iops']}")
print(f"推荐 IOPS: {iops['recommended_iops']:.0f}")

# 连接数估算
connections = planner.estimate_connections({
    'app_instances': 20,
    'pool_size': 20
})

print("\n=== 连接数规划 ===")
print(f"应用实例: {connections['app_instances']}")
print(f"连接池大小: {connections['pool_size']}")
print(f"总连接数: {connections['total_connections']}")
print(f"推荐最大连接数: {connections['recommended_max']}")
```

## 🎯 面试题精选

### 面试题 1：什么是容量规划？为什么它重要？

**考察点**：对容量规划概念的理解。

**参考答案要点**：
1. 容量规划是确保系统有足够资源满足当前和未来需求的过程
2. 重要性：避免资源不足导致故障、避免过度配置浪费成本
3. 包含短期、中期、长期规划
4. 需要考虑业务增长、季节性变化、技术演进

### 面试题 2：如何进行需求预测？

**考察点**：对需求预测方法的掌握。

**参考答案要点**：
1. 趋势分析：基于历史数据预测未来增长
2. 季节性分析：识别业务的周期性特征
3. 峰值因子：考虑流量峰值与平均值的比例
4. 安全系数：通常取 1.2-1.5 的安全余量

### 面试题 3：HPA 是如何工作的？

**考察点**：对 Kubernetes 自动扩缩容的理解。

**参考答案要点**：
1. HPA 基于指标自动调整 Pod 副本数
2. 计算公式：期望副本数 = ceil(当前副本数 × (当前指标 / 目标指标))
3. 支持 CPU、内存、自定义指标
4. 有稳定窗口期防止频繁抖动

### 面试题 4：如何评估数据库的容量需求？

**考察点**：对数据库容量规划的理解。

**参考答案要点**：
1. 存储容量：当前数据 + 增长预测 + 索引 + 安全余量
2. IOPS 需求：基于读写 QPS 和每查询 I/O 数
3. 连接数：应用实例数 × 连接池大小
4. 内存：热数据大小应小于可用内存

### 面试题 5：什么是压力测试？有哪些类型？

**考察点**：对压力测试方法的理解。

**参考答案要点**：
1. 负载测试：验证预期负载下的表现
2. 压力测试：找到系统极限
3. 浸泡测试：验证长时间运行稳定性
4. 尖峰测试：验证应对突发流量能力

### 面试题 6：如何设计弹性伸缩策略？

**考察点**：对自动扩缩容策略的理解。

**参考答案要点**：
1. HPA：水平扩展 Pod 数量
2. VPA：垂直调整 Pod 资源
3. Cluster Autoscaler：扩展集群节点
4. 扩容快速响应，缩容稳定保守
