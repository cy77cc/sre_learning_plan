### 1. CKA — Certified Kubernetes Administrator

#### 1.1 认证概述

```
CKA 是 CNCF 官方的 Kubernetes 管理员认证。

基本信息：
- 考试机构：CNCF + Linux Foundation
- 考试形式：在线实操（命令行操作真实集群）
- 考试时间：2 小时
- 题目数量：15-20 道
- 通过分数：66%
- 费用：395 美元
- 有效期：3 年
- 考试环境：Chrome 浏览器 + 远程桌面

考试范围（权重）：
1. 集群架构、安装和配置（25%）
   - 使用 kubeadm 管理集群
   - 备份和恢复 etcd
   - 高可用集群

2. 工作负载和调度（15%）
   - Pod 调度
   - 资源管理
   - ConfigMap 和 Secret

3. 服务和网络（20%）
   - Service 和 Endpoint
   - Ingress
   - CoreDNS
   - 网络策略

4. 存储（10%）
   - PV 和 PVC
   - StorageClass

5. 故障排查（30%）
   - 评估集群和节点日志
   - 监控集群组件
   - 应用故障排查
   - 网络故障排查
```

#### 1.2 学习路径

```
第一阶段：基础巩固（2 周）
- 复习 Kubernetes 核心概念
- 熟练使用 kubectl 命令
- 理解集群架构

第二阶段：考试专题（3 周）
- 集群安装和配置
- 网络和存储
- 故障排查

第三阶段：模拟练习（2 周）
- 完成 Killer.sh 模拟题
- 练习历年真题
- 限时练习

第四阶段：考前冲刺（1 周）
- 查漏补缺
- 熟悉考试环境
- 准备参考资料

每日学习计划：
- 早上 1 小时：理论学习
- 晚上 2 小时：实操练习
- 周末：模拟考试
```

#### 1.3 高频考点

```
1. etcd 备份和恢复
   # 备份
   $ ETCDCTL_API=3 etcdctl snapshot save /backup/etcd-snapshot.db \
     --endpoints=https://127.0.0.1:2379 \
     --cacert=/etc/kubernetes/pki/etcd/ca.crt \
     --cert=/etc/kubernetes/pki/etcd/server.crt \
     --key=/etc/kubernetes/pki/etcd/server.key

   # 恢复
   $ ETCDCTL_API=3 etcdctl snapshot restore /backup/etcd-snapshot.db \
     --data-dir=/var/lib/etcd-restore

2. kubeadm 集群升级
   # 升级控制平面
   $ kubeadm upgrade plan
   $ kubeadm upgrade apply v1.28.0

   # 升级节点
   $ kubectl drain <node>
   $ kubeadm upgrade node
   $ apt-get update && apt-get install -y kubelet=1.28.0-00
   $ systemctl daemon-reload
   $ systemctl restart kubelet
   $ kubectl uncordon <node>

3. NetworkPolicy
   apiVersion: networking.k8s.io/v1
   kind: NetworkPolicy
   metadata:
     name: deny-all
   spec:
     podSelector: {}
     policyTypes:
       - Ingress
       - Egress

4. Ingress 配置
   apiVersion: networking.k8s.io/v1
   kind: Ingress
   metadata:
     name: my-ingress
   spec:
     rules:
       - host: example.com
         http:
           paths:
             - path: /api
               pathType: Prefix
               backend:
                 service:
                   name: api-service
                   port:
                     number: 80

5. Node 故障排查
   $ journalctl -u kubelet
   $ systemctl status kubelet
   $ kubectl describe node <node>
```

#### 1.4 考试技巧

```
1. 时间管理
   - 每题平均 6-8 分钟
   - 先做简单的，再做难的
   - 标记不确定的题目，最后回来

2. 使用 kubectl 速查
   - 考试允许使用官方文档
   - 提前熟悉文档结构
   - 使用 kubectl cheat sheet

3. 快捷操作

   # 快速生成 YAML
   kubectl run nginx --image=nginx $do > pod.yaml

   # 使用 --edit 直接编辑
   kubectl edit deployment/my-app

4. 注意事项
   - 仔细审题，注意命名空间
   - 确认操作的集群和上下文
   - 检查 Pod 是否正常运行
   - 注意 YAML 缩进
```

```
1. Pod Security Standards
   # 限制特权容器
   apiVersion: v1
   kind: Namespace
   metadata:
     name: secure-ns
     labels:
       pod-security.kubernetes.io/enforce: restricted

2. Trivy 镜像扫描
   $ trivy image --severity HIGH,CRITICAL nginx:latest

3. Falco 规则
   - rule: Terminal shell in container
     condition: >
       spawned_process and container and
       proc.name in (bash, sh, zsh)
     output: >
       Shell spawned in container
       (user=%user.name container=%container.name)
     priority: WARNING

4. NetworkPolicy
   # 只允许特定 Pod 访问
   apiVersion: networking.k8s.io/v1
   kind: NetworkPolicy
   metadata:
     name: allow-frontend
   spec:
     podSelector:
       matchLabels:
         app: backend
     ingress:
       - from:
           - podSelector:
               matchLabels:
                 app: frontend

5. etcd 加密
   apiVersion: apiserver.config.k8s.io/v1
   kind: EncryptionConfiguration
   resources:
     - resources:
         - secrets
       providers:
         - aescbc:
             keys:
               - name: key1
                 secret: <base64-encoded-secret>
         - identity: {}
```

```
1. Terraform 工作流

   $ terraform destroy    # 销毁资源

   $ terraform state list                # 列出资源
   $ terraform state show <resource>     # 显示资源
   $ terraform state mv <old> <new>      # 移动资源

3. 变量类型

     }
   }

4. 模块
   module "vpc" {
     source  = "terraform-aws-modules/vpc/aws"

   }

5. Remote State
   terraform {
     backend "s3" {
       bucket = "my-terraform-state"

     }
   }

6. Lifecycle
   resource "aws_instance" "web" {
     ami           = "ami-12345"
     instance_type = "t3.micro"

     lifecycle {
       create_before_destroy = true
       prevent_destroy       = false
       ignore_changes        = [tags]
     }
   }
```

#### 4.4 模拟题

```
题目 1：terraform plan 命令的作用是？
A. 应用变更
B. 预览变更
C. 销毁资源
D. 初始化项目

答案：B
解析：terraform plan 预览将要执行的变更，不会实际执行。

题目 2：如何将 State 文件存储在远程？
A. 使用 terraform push
B. 配置 backend
C. 使用 terraform state
D. 使用 terraform remote

答案：B
解析：通过配置 backend（如 S3、Consul）实现远程 State 存储。

题目 3：terraform import 命令的作用是？
A. 导入变量
B. 导入模块
C. 将现有资源导入 State
D. 导入 Provider

答案：C
解析：terraform import 将现有基础设施资源导入 Terraform 管理。

题目 4：什么是 Terraform 的"计划"（Plan）阶段？
A. 下载 Provider
B. 创建资源
C. 计算资源变更
D. 销毁资源

答案：C
解析：Plan 阶段计算当前状态与期望状态的差异。

题目 5：如何防止资源被意外销毁？
A. 使用 terraform lock
B. 设置 prevent_destroy = true
C. 使用 terraform protect
D. 设置 immutable = true

答案：B
解析：lifecycle 中设置 prevent_destroy = true 可防止资源被销毁。
```

### 练习 3：CKS 安全实践

```bash
# 1. 镜像扫描
$ trivy image nginx:latest

# 2. Pod Security Standards
$ kubectl label namespace default pod-security.kubernetes.io/enforce=restricted

# 3. NetworkPolicy
cat <<EOF | kubectl apply -f -
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all
  namespace: default
spec:
  podSelector: {}
  policyTypes:
    - Ingress
    - Egress
EOF
```
