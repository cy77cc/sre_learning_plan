### 2. SAST（静态应用安全测试）

#### 2.1 Semgrep

```yaml
# .semgrep.yml - 自定义规则
rules:
  # 检测 SQL 注入
  - id: sql-injection
    patterns:
      - pattern: |
          $QUERY = "SELECT * FROM " + $TABLE + " WHERE " + $COLUMN + " = " + $USER_INPUT
    message: |
      检测到潜在的 SQL 注入漏洞。
      使用参数化查询替代字符串拼接。
    severity: ERROR
    languages: [python]
    metadata:
      cwe:
        - "CWE-89: Improper Neutralization of Special Elements used in an SQL Command"
      owasp:
        - A03:2021 - Injection

  # 检测硬编码密码
  - id: hardcoded-password
    pattern-either:
      - pattern: |
          password = "..."
      - pattern: |
          PASSWORD = "..."
      - pattern: |
          secret = "..."
    message: |
      检测到硬编码的密码或密钥。
      使用环境变量或密钥管理服务。
    severity: WARNING
    languages: [python, javascript, go]

  # 检测不安全的随机数
  - id: insecure-random
    pattern-either:
      - pattern: random.random()
      - pattern: random.randint(...)
    message: |
      使用了不安全的随机数生成器。
      对于安全相关场景，使用 secrets 模块。
    severity: WARNING
    languages: [python]

  # 检测 eval 使用
  - id: dangerous-eval
    pattern-either:
      - pattern: eval(...)
      - pattern: exec(...)
    message: |
      检测到 eval/exec 使用，存在代码注入风险。
    severity: ERROR
    languages: [python, javascript]
```

```bash
# 安装 Semgrep
pip install semgrep

# 运行扫描
semgrep --config=auto .

# 使用特定规则集
semgrep --config=p/owasp-top-ten .
semgrep --config=p/security-audit .
semgrep --config=p/python .

# CI/CD 集成
semgrep --config=auto --error --json --output=semgrep-results.json .
```

#### 2.2 CodeQL

```yaml
# .github/workflows/codeql.yml
name: "CodeQL Analysis"

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  schedule:
    - cron: '0 6 * * 1'  # 每周一早上 6 点

jobs:
  analyze:
    name: Analyze
    runs-on: ubuntu-latest
    permissions:
      security-events: write

    strategy:
      fail-fast: false
      matrix:
        language: ['python', 'javascript', 'go']

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Initialize CodeQL
        uses: github/codeql-action/init@v3
        with:
          languages: ${{ matrix.language }}
          queries: security-extended

      - name: Autobuild
        uses: github/codeql-action/autobuild@v3

      - name: Perform CodeQL Analysis
        uses: github/codeql-action/analyze@v3
        with:
          category: "/language:${{ matrix.language }}"
```

### 3. DAST（动态应用安全测试）

#### 3.1 OWASP ZAP

```yaml
# OWASP ZAP Docker 扫描
# zap-scan.yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: zap-scan
  namespace: security
spec:
  template:
    spec:
      containers:
        - name: zap
          image: ghcr.io/zaproxy/zaproxy:stable
          command:
            - zap-baseline.py
            - -t
            - https://myapp.example.com
            - -r
            - zap-report.html
            - -J
            - zap-report.json
          volumeMounts:
            - name: report
              mountPath: /zap/wrk
      volumes:
        - name: report
          emptyDir: {}
      restartPolicy: Never
```

```bash
# 本地运行 OWASP ZAP
docker run -t ghcr.io/zaproxy/zaproxy:stable zap-baseline.py \
  -t https://myapp.example.com \
  -r report.html

# API 扫描
docker run -t ghcr.io/zaproxy/zaproxy:stable zap-api-scan.py \
  -t https://myapp.example.com/openapi.json \
  -f openapi \
  -r api-report.html

# 全量扫描
```

#### 5.2 Trivy 使用

```bash
# 安装 Trivy
# Ubuntu/Debian
sudo apt-get install trivy

# macOS
brew install trivy

# Docker
docker pull aquasec/trivy

# ===== 文件系统扫描 =====
# 扫描当前目录
trivy fs --security-checks vuln,config .

# 只显示 HIGH 和 CRITICAL 漏洞
trivy fs --severity HIGH,CRITICAL .

# JSON 输出
trivy fs --format json --output results.json .

# ===== 镜像扫描 =====
# 扫描镜像
trivy image myapp:latest

# 只显示 HIGH 和 CRITICAL
trivy image --severity HIGH,CRITICAL myapp:latest

# 扫描并退出码（CI 集成）
trivy image --exit-code 1 --severity CRITICAL myapp:latest

# JSON 输出
trivy image --format json --output image-results.json myapp:latest

# ===== 仓库扫描 =====
trivy repo --security-checks vuln,secret https://github.com/myorg/myapp

# ===== 配置扫描 =====
trivy config --severity HIGH,CRITICAL .

# ===== K8s 扫描 =====
trivy k8s --report summary cluster
trivy k8s --namespace production all
```

#### 5.3 CI/CD 集成

```yaml
# GitHub Actions Trivy 扫描
name: Trivy Security Scan

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  trivy-fs:
    name: Filesystem Scan
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Run Trivy filesystem scan
        uses: aquasecurity/trivy-action@master
        with:
          scan-type: 'fs'
          scan-ref: '.'
          severity: 'HIGH,CRITICAL'
          format: 'sarif'
          output: 'trivy-fs-results.sarif'

      - name: Upload Trivy scan results to GitHub Security
        uses: github/codeql-action/upload-sarif@v3
        if: always()
        with:
          sarif_file: 'trivy-fs-results.sarif'

  trivy-image:
    name: Container Image Scan
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Run Trivy image scan
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: 'myregistry/myapp:${{ github.sha }}'
          severity: 'HIGH,CRITICAL'
          exit-code: '1'
          format: 'table'

  trivy-config:
    name: IaC Config Scan
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Run Trivy config scan
        uses: aquasecurity/trivy-action@master
        with:
          scan-type: 'config'
          scan-ref: '.'
          severity: 'HIGH,CRITICAL'
          exit-code: '1'
```

```
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  SBOM 格式:                                                  │   │
│  │  ├── SPDX (Linux Foundation)                                 │   │
│  │  ├── CycloneDX (OWASP)                                       │   │
│  │  └── SWID (ISO/IEC 19770-2)                                 │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │

│  │  ├── Syft (Anchore) - 生成 SBOM                             │   │

│  │  └── CycloneDX tools - CycloneDX 格式工具                   │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  使用场景:                                                          │
│  ├── 合规要求（美国行政命令）                                      │
│  ├── 漏洞管理（快速识别受影响组件）                                │
│  ├── 许可证合规                                                    │
│  ├── 供应链安全                                                    │
│  └── 审计追踪                                                      │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 6.2 SBOM 生成

```bash
# 使用 Syft 生成 SBOM
# 安装 Syft
curl -sSfL https://raw.githubusercontent.com/anchore/syft/main/install.sh | sh -s

# 生成 SPDX 格式 SBOM
syft myapp:latest -o spdx-json > sbom-spdx.json

# 生成 CycloneDX 格式 SBOM
syft myapp:latest -o cyclonedx-json > sbom-cyclonedx.json

# 生成表格格式（人类可读）
syft myapp:latest -o table

# 使用 Trivy 生成 SBOM
trivy image --format spdx-json --output sbom-spdx.json myapp:latest
trivy image --format cyclonedx --output sbom-cyclonedx.json myapp:latest

# 使用 Grype 扫描 SBOM 中的漏洞
grype sbom:sbom-spdx.json
```

#### 8.2 Gatekeeper 策略配置

```yaml
# ConstraintTemplate - 要求镜像来自可信仓库
apiVersion: templates.gatekeeper.sh/v1
kind: ConstraintTemplate
metadata:
  name: k8sallowedrepos
spec:
  crd:
    spec:
      names:
        kind: K8sAllowedRepos
      validation:
        openAPIV3Schema:
          type: object
          properties:
            repos:
              type: array
              items:
                type: string
  targets:
    - target: admission.k8s.gatekeeper.sh
      rego: |
        package k8sallowedrepos

        violation[{"msg": msg}] {
          container := input.review.object.spec.containers[_]
          not startswith(container.image, input.parameters.repos[_])
          msg := sprintf("Container image '%v' is not from an allowed repository. Allowed repos: %v", [container.image, input.parameters.repos])
        }

        violation[{"msg": msg}] {
          container := input.review.object.spec.initContainers[_]
          not startswith(container.image, input.parameters.repos[_])
          msg := sprintf("Init container image '%v' is not from an allowed repository. Allowed repos: %v", [container.image, input.parameters.repos])
        }

---
# Constraint - 允许的镜像仓库
apiVersion: constraints.gatekeeper.sh/v1beta1
kind: K8sAllowedRepos
metadata:
  name: allowed-repos
spec:
  match:
    kinds:
      - apiGroups: [""]
        kinds: ["Pod"]
    namespaces:
      - production
      - staging
  parameters:
    repos:
      - "myregistry.azurecr.io/"
      - "ghcr.io/myorg/"
      - "docker.io/library/"  # 官方镜像

---
# ConstraintTemplate - 要求资源限制
apiVersion: templates.gatekeeper.sh/v1
kind: ConstraintTemplate
metadata:
  name: k8srequiredresources
spec:
  crd:
    spec:
      names:
        kind: K8sRequiredResources
  targets:
    - target: admission.k8s.gatekeeper.sh
      rego: |
        package k8srequiredresources

        violation[{"msg": msg}] {
          container := input.review.object.spec.containers[_]
          not container.resources.limits.memory
          msg := sprintf("Container '%v' does not have a memory limit", [container.name])
        }

        violation[{"msg": msg}] {
          container := input.review.object.spec.containers[_]
          not container.resources.limits.cpu
          msg := sprintf("Container '%v' does not have a CPU limit", [container.name])
        }

        violation[{"msg": msg}] {
          container := input.review.object.spec.containers[_]
          not container.resources.requests.memory
          msg := sprintf("Container '%v' does not have a memory request", [container.name])
        }

        violation[{"msg": msg}] {
          container := input.review.object.spec.containers[_]
          not container.resources.requests.cpu
          msg := sprintf("Container '%v' does not have a CPU request", [container.name])
        }

---
# Constraint - 生产环境必须设置资源限制
apiVersion: constraints.gatekeeper.sh/v1beta1
kind: K8sRequiredResources
metadata:
  name: require-resource-limits
spec:
  match:
    kinds:
      - apiGroups: [""]
        kinds: ["Pod"]
    namespaces:
      - production
```

#### 9.2 cosign 使用

```bash
# 安装 cosign
# Linux
wget https://github.com/sigstore/cosign/releases/latest/download/cosign-linux-amd64
chmod +x cosign-linux-amd64
sudo mv cosign-linux-amd64 /usr/local/bin/cosign

# macOS
brew install cosign

# ===== 生成密钥对 =====
cosign generate-key-pair
# 生成 cosign.key (私钥) 和 cosign.pub (公钥)

# ===== 签名镜像 =====
# 使用密钥签名
cosign sign --key cosign.key myregistry/myapp:v1.0.0

# 使用 OIDC 身份签名（无需管理密钥）
cosign sign --identity-token=$(gcloud auth print-identity-token) myregistry/myapp:v1.0.0

# 附加 SBOM
cosign attach sbom --sbom sbom.spdx.json myregistry/myapp:v1.0.0

# 附加漏洞报告
cosign attest --key cosign.key --type vuln --predicate vuln.json myregistry/myapp:v1.0.0

# ===== 验证签名 =====
# 验证签名
cosign verify --key cosign.pub myregistry/myapp:v1.0.0

# 验证并检查特定声明
cosign verify --key cosign.pub \
  --check-identity-regexp=".*@mycompany.com" \
  myregistry/myapp:v1.0.0

# 验证 SBOM
cosign verify-attestation --key cosign.pub --type spdxjson myregistry/myapp:v1.0.0
```

## 实战练习

### 练习 1: 使用 Trivy 扫描容器镜像

**目标:** 使用 Trivy 扫描容器镜像，发现并修复 CVE 漏洞。

```bash
# 步骤 1: 安装 Trivy
sudo apt-get install trivy

# 步骤 2: 扫描官方镜像
trivy image nginx:1.24

# 步骤 3: 只显示 HIGH 和 CRITICAL
trivy image --severity HIGH,CRITICAL nginx:1.24

# 步骤 4: 扫描自定义镜像
cat > Dockerfile << 'EOF'
FROM python:3.11
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "app.py"]
EOF

echo "flask==2.3.0" > requirements.txt
echo "requests==2.28.0" >> requirements.txt

docker build -t myapp:latest .

# 步骤 5: 扫描自定义镜像
trivy image --severity HIGH,CRITICAL myapp:latest

# 步骤 6: 修复漏洞
# 更新 requirements.txt 中的版本
echo "flask==3.0.0" > requirements.txt
echo "requests==2.31.0" >> requirements.txt

# 重新构建和扫描
docker build -t myapp:fixed .
trivy image --severity HIGH,CRITICAL myapp:fixed
```

### 练习 2: 生成 SBOM 并扫描漏洞

**目标:** 使用 Syft 生成 SBOM，使用 Grype 扫描 SBOM 中的漏洞。

```bash
# 步骤 1: 安装 Syft 和 Grype
curl -sSfL https://raw.githubusercontent.com/anchore/syft/main/install.sh | sh
curl -sSfL https://raw.githubusercontent.com/anchore/grype/main/install.sh | sh

# 步骤 2: 生成 SBOM
syft nginx:latest -o spdx-json > nginx-sbom.json
syft nginx:latest -o table

# 步骤 3: 使用 Grype 扫描 SBOM
grype sbom:nginx-sbom.json

# 步骤 4: 只显示 HIGH 和 CRITICAL
grype sbom:nginx-sbom.json --only-fixed --fail-on high

# 步骤 5: JSON 输出
grype sbom:nginx-sbom.json -o json > grype-results.json

# 步骤 6: 使用 Trivy 生成 SBOM
trivy image --format spdx-json --output nginx-trivy-sbom.json nginx:latest
```

### 练习 3: 配置 OPA Gatekeeper 策略

**目标:** 配置 Gatekeeper 策略，限制生产环境只能使用可信镜像仓库。

```bash
# 步骤 1: 安装 Gatekeeper
kubectl apply -f https://raw.githubusercontent.com/open-policy-agent/gatekeeper/v3.15.0/deploy/gatekeeper.yaml

# 步骤 2: 创建 ConstraintTemplate
cat <<EOF | kubectl apply -f -
apiVersion: templates.gatekeeper.sh/v1
kind: ConstraintTemplate
metadata:
  name: k8sallowedrepos
spec:
  crd:
    spec:
      names:
        kind: K8sAllowedRepos
      validation:
        openAPIV3Schema:
          type: object
          properties:
            repos:
              type: array
              items:
                type: string
  targets:
    - target: admission.k8s.gatekeeper.sh
      rego: |
        package k8sallowedrepos
        violation[{"msg": msg}] {
          container := input.review.object.spec.containers[_]
          not startswith(container.image, input.parameters.repos[_])
          msg := sprintf("Image '%v' is not from allowed repos: %v", [container.image, input.parameters.repos])
        }
EOF

# 步骤 3: 创建 Constraint
cat <<EOF | kubectl apply -f -
apiVersion: constraints.gatekeeper.sh/v1beta1
kind: K8sAllowedRepos
metadata:
  name: allowed-repos-prod
spec:
  match:
    kinds:
      - apiGroups: [""]
        kinds: ["Pod"]
    namespaces:
      - production
  parameters:
    repos:
      - "nginx:"
      - "myregistry.azurecr.io/"
EOF

# 步骤 4: 测试策略
# 应该被阻断
kubectl run test --image=malicious/image -n production
# Error: admission webhook "validation.gatekeeper.sh" denied the request

# 应该被允许
kubectl run test --image=nginx:latest -n production
# pod/test created

# 步骤 5: 查看审计结果
kubectl get k8sallowedrepos -o yaml
```

## 面试题精选

### 1. SAST、DAST 和 SCA 有什么区别？

**参考答案：**

| 维度 | SAST | DAST | SCA |
|------|------|------|-----|
| 扫描时机 | 编码阶段 | 运行阶段 | 编码/构建阶段 |
| 扫描对象 | 源代码 | 运行中应用 | 依赖组件 |
| 检测内容 | 代码漏洞 | Web 漏洞 | CVE、许可证 |
| 误报率 | 中 | 低 | 低 |
| 工具 | Semgrep、CodeQL | OWASP ZAP | Dependabot、Snyk |

三者互补，完整的安全扫描应覆盖所有类型。

### 2. 什么是 SBOM？为什么需要它？

**参考答案：**

SBOM（Software Bill of Materials）是软件的"配料表"，列出所有组件、依赖、版本和许可证信息。

需要原因：
1. **漏洞管理**：当新 CVE 发布时，快速识别受影响的软件
2. **合规要求**：美国行政命令要求供应商提供 SBOM
3. **许可证合规**：确保不使用限制性许可证
4. **供应链安全**：追踪软件供应链中的风险

### 3. Trivy 有哪些扫描模式？各适用于什么场景？

**参考答案：**

- **trivy fs**：扫描文件系统，适用于 CI 中扫描项目依赖
- **trivy image**：扫描容器镜像，适用于构建后扫描镜像漏洞
- **trivy repo**：扫描 Git 仓库，适用于代码审查
- **trivy config**：扫描 IaC 配置，适用于 Terraform/K8s 配置审查
- **trivy k8s**：扫描 K8s 集群，适用于运行时安全审计

### 4. 什么是 Policy-as-Code？OPA Gatekeeper 如何工作？

**参考答案：**

Policy-as-Code 是将安全策略用代码定义和管理的理念。

OPA Gatekeeper 工作流程：
1. 定义 ConstraintTemplate（Rego 策略语言）
2. 创建 Constraint（具体约束实例）
3. Gatekeeper 作为 Admission Webhook 运行
4. 拦截不合规的资源创建/更新请求
5. 审计模式：只报告不阻断
6. 强制模式：不合规则拒绝

### 5. cosign 如何保证镜像供应链安全？

**参考答案：**

cosign 通过数字签名保证镜像安全：
1. **签名**：构建时使用私钥签名镜像
2. **验证**：部署时使用公钥验证签名
3. **不可篡改**：签名绑定镜像摘要，任何修改都会导致验证失败
4. **身份绑定**：通过 OIDC 绑定签名者身份
5. **透明日志**：Rekor 记录所有签名操作

### 6. 如何在 CI/CD 中实现安全门控？

**参考答案：**

安全门控实现：
1. **SAST 门控**：代码扫描发现 CRITICAL 漏洞则阻断
2. **依赖门控**：依赖扫描发现 HIGH/CRITICAL CVE 则阻断
3. **镜像门控**：镜像扫描发现 CRITICAL CVE 则阻断
4. **签名门控**：镜像签名验证失败则阻断部署
5. **配置门控**：K8s 配置不合规则阻断部署

关键：门控必须自动化，失败时提供清晰的修复指引。

### 7. Dependabot 和 Snyk 有什么区别？

**参考答案：**

| 特性 | Dependabot | Snyk |
|------|------------|------|
| 来源 | GitHub 原生 | 独立公司 |
| 功能 | 依赖更新 PR | 扫描 + 修复建议 |
| 覆盖 | GitHub 仓库 | 多平台 |
| 价格 | 免费 | 免费+付费 |
| 集成 | GitHub 深度集成 | 多工具集成 |
| 修复 | 自动 PR | PR + 优先级排序 |

选择：GitHub 项目用 Dependabot，企业用 Snyk。

### 8. 如何处理扫描发现的 CVE？

**参考答案：**

处理流程：
1. **评估严重程度**：CRITICAL/HIGH 需要立即处理
2. **确认影响范围**：是否影响生产环境
3. **查找修复版本**：查看 CVE 详情和修复版本
4. **升级依赖**：更新到安全版本
5. **验证修复**：重新扫描确认漏洞已修复
6. **无法修复**：添加例外说明，定期复查

### 9. 什么是镜像签名的"不可变性"？

**参考答案：**

镜像签名的不可变性指：
1. 签名绑定镜像的 digest（SHA256 摘要）
2. 任何对镜像内容的修改都会改变 digest
3. 修改后的镜像无法通过原始签名验证
4. 保证镜像从构建到部署未被篡改

这确保了"你构建的就是你部署的"。

### 10. 如何平衡安全扫描和开发效率？

**参考答案：**

平衡策略：
1. **分级门控**：CRITICAL 阻断，HIGH 警告，MEDIUM/LOW 记录
2. **增量扫描**：只扫描变更的代码和依赖
3. **缓存结果**：避免重复扫描未变更部分
4. **异步扫描**：非阻断扫描在后台运行
5. **自动修复**：Dependabot 自动创建修复 PR
6. **白名单**：已知无风险的漏洞可以添加例外
7. **反馈循环**：扫描结果集成到 IDE，提前发现问题
