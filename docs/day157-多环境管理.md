#### 1.2 环境特性对比

```
┌──────────────┬─────────────────┬─────────────────┬─────────────────┐
│ 特性          │ DEV             │ STAGING         │ PRODUCTION      │
├──────────────┼─────────────────┼─────────────────┼─────────────────┤
│ 部署触发      │ 自动(push)      │ 自动(main merge)│ 手动+审批       │
│ 副本数        │ 1               │ 2-3             │ 3+              │
│ 资源限制      │ 无/宽松         │ 接近生产        │ 严格            │
│ 日志级别      │ DEBUG           │ INFO            │ WARN            │
│ 监控告警      │ 基础            │ 完整            │ 完整+P1值班     │
│ 数据          │ 测试数据        │ 脱敏生产数据    │ 真实数据        │
│ 外部依赖      │ Mock            │ 测试环境        │ 生产环境        │
│ 变更频率      │ 高(每天多次)    │ 中(每天1-2次)   │ 低(每周1-2次)   │
│ 回滚方式      │ 自动            │ 自动            │ 手动            │
│ SLA           │ 无              │ 低              │ 高              │
└──────────────┴─────────────────┴─────────────────┴─────────────────┘
```

### 2. Kustomize 多环境管理

#### 2.1 Kustomize 目录结构

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Kustomize 目录结构                                 │
│                                                                     │
│  k8s/                                                               │
│  ├── base/                     # 基础配置（共享）                    │
│  │   ├── kustomization.yaml    # 基础 kustomize 配置                │
│  │   ├── deployment.yaml       # 基础 Deployment                    │
│  │   ├── service.yaml          # 基础 Service                      │
│  │   ├── configmap.yaml        # 基础 ConfigMap                     │
│  │   └── ingress.yaml          # 基础 Ingress                      │
│  │                                                                   │
│  └── overlays/                 # 环境覆盖（差异）                    │
│      ├── dev/                  # DEV 环境覆盖                       │
│      │   ├── kustomization.yaml                                      │
│      │   ├── namespace.yaml                                          │
│      │   ├── replica-patch.yaml                                      │
│      │   └── resource-patch.yaml                                     │
│      │                                                                │
│      ├── staging/              # STAGING 环境覆盖                   │
│      │   ├── kustomization.yaml                                      │
│      │   ├── namespace.yaml                                          │
│      │   ├── replica-patch.yaml                                      │
│      │   └── resource-patch.yaml                                     │
│      │                                                                │
│      └── production/           # PRODUCTION 环境覆盖                │
│          ├── kustomization.yaml                                      │
│          ├── namespace.yaml                                          │
│          ├── replica-patch.yaml                                      │
│          ├── resource-patch.yaml                                     │
│          └── hpa.yaml                                                │
│                                                                     │
│  原理:                                                              │
│  base/ 定义通用配置                                                  │
│  overlays/ 通过 patch 修改差异                                       │
│  kustomize build overlays/production → 最终 YAML                    │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 2.2 Base 配置

```yaml
# base/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

metadata:
  name: myapp

# 公共标签
commonLabels:
  app: myapp
  managed-by: kustomize

# 公共注解
commonAnnotations:
  team: backend

# 资源列表
resources:
  - deployment.yaml
  - service.yaml
  - configmap.yaml
  - ingress.yaml

# 镜像（会被 overlay 覆盖）
images:
  - name: myapp
    newName: myregistry/myapp
    newTag: v1.0.0
```

```yaml
# base/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  replicas: 1
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
        - name: myapp
          image: myapp
          ports:
            - containerPort: 8080

            - configMapRef:
                name: myapp-config

            requests:
              cpu: 100m

              cpu: 500m
              memory: 256Mi
          livenessProbe:
            httpGet:
              path: /healthz
              port: 8080
            initialDelaySeconds: 15
            periodSeconds: 10
          readinessProbe:
            httpGet:
              path: /readyz
              port: 8080
            initialDelaySeconds: 5
            periodSeconds: 5
```

```yaml

kind: Service

  name: myapp

  ports:
    - port: 80

      name: http

    app: myapp
```

#### 2.3 Overlay 配置

```yaml
# overlays/dev/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

# 继承 base
resources:
  - ../../base

# 命名空间
namespace: dev

# 名称前缀
namePrefix: dev-

# 公共标签
commonLabels:
  environment: dev

# 覆盖镜像标签
images:
  - name: myapp
    newTag: dev-latest

# 补丁
patches:
  # 副本数补丁
  - target:
      kind: Deployment
      name: myapp
    patch: |
      - op: replace
        path: /spec/replicas
        value: 1

  # 资源限制补丁（放宽）
  - target:
      kind: Deployment
      name: myapp
    patch: |
      - op: replace
        path: /spec/template/spec/containers/0/resources
        value:
          requests:
            cpu: 50m
            memory: 64Mi
          limits:
            cpu: 200m
            memory: 256Mi

  # 日志级别补丁
  - target:
      kind: ConfigMap
      name: myapp-config
    patch: |
      - op: replace
        path: /data/LOG_LEVEL
        value: "debug"
      - op: replace
        path: /data/DB_HOST
        value: "dev-db.dev.svc.cluster.local"

# 额外资源
resources:
  - namespace.yaml
```

```yaml
# overlays/dev/namespace.yaml
apiVersion: v1
kind: Namespace
metadata:
  name: dev
  labels:
    environment: dev
```

### 3. Helm 多环境管理

#### 3.1 Helm Values 文件结构

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Helm 多环境 Values 结构                            │
│                                                                     │
│  myapp-chart/                                                       │
│  ├── Chart.yaml                  # Chart 元数据                     │
│  ├── values.yaml                 # 默认值（base）                   │
│  ├── values-dev.yaml             # DEV 环境覆盖                     │
│  ├── values-staging.yaml         # STAGING 环境覆盖                 │
│  ├── values-production.yaml      # PRODUCTION 环境覆盖              │

│  │   ├── service.yaml                                             │
│  │   ├── ingress.yaml                                             │
│  │   ├── hpa.yaml                                                 │
│  │   └── configmap.yaml                                           │
│  └── charts/                    # 依赖 Chart                       │
│                                                                     │
│  使用方式:                                                          │
│  helm install myapp ./myapp-chart -f values-production.yaml        │
```

#### 3.3 Helm 部署命令

```bash
# DEV 环境部署
helm install myapp-dev ./myapp-chart \
  -f values.yaml \
  -f values-dev.yaml \
  --namespace dev \
  --create-namespace

# STAGING 环境部署
helm install myapp-staging ./myapp-chart \
  -f values.yaml \
  -f values-staging.yaml \
  --namespace staging \
  --create-namespace

# PRODUCTION 环境部署
helm install myapp-prod ./myapp-chart \
  -f values.yaml \
  -f values-production.yaml \
  --namespace production \
  --create-namespace

# 升级
helm upgrade myapp-prod ./myapp-chart \
  -f values.yaml \
  -f values-production.yaml \
  --set image.tag=v1.2.4

# 回滚
helm rollback myapp-prod 1
```

### 4. ArgoCD ApplicationSet 多环境

#### 4.1 ApplicationSet 配置

```yaml
# applicationset-multi-env.yaml
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: myapp-multi-env
  namespace: argocd
spec:
  # 生成器: 定义环境列表
  generators:
    - list:
        elements:
          # DEV 环境
          - env: dev
            cluster: https://kubernetes.default.svc
            namespace: dev
            revision: develop
            autoSync: "true"
            selfHeal: "true"
            prune: "true"
          # STAGING 环境
          - env: staging
            cluster: https://kubernetes.default.svc
            namespace: staging
            revision: main
            autoSync: "true"
            selfHeal: "true"
            prune: "true"
          # PRODUCTION 环境
          - env: production
            cluster: https://kubernetes.default.svc
            namespace: production
            revision: main
            autoSync: "false"
            selfHeal: "false"
            prune: "false"

  # 模板: 定义 Application 模板
  template:
    metadata:
      name: 'myapp-{{env}}'
      namespace: argocd
      labels:
        environment: '{{env}}'
        app: myapp
    spec:
      project: '{{env}}'

      source:
        repoURL: https://github.com/myorg/k8s-manifests.git
        targetRevision: '{{revision}}'
        path: 'apps/myapp/overlays/{{env}}'

      destination:
        server: '{{cluster}}'
        namespace: '{{namespace}}'

      syncPolicy:
        automated:
          selfHeal: '{{selfHeal}}'
          prune: '{{prune}}'
        syncOptions:
          - CreateNamespace=true
          - ServerSideApply=true

  # 滚动同步策略
  strategy:
    type: RollingSync
    rollingSync:
      steps:
        # 先同步 DEV
        - matchExpressions:
            - key: env
              operator: In
              values:
                - dev
        # 再同步 STAGING
        - matchExpressions:
            - key: env
              operator: In
              values:
                - staging
        # 最后同步 PRODUCTION
        - matchExpressions:
            - key: env
              operator: In
              values:
                - production
```

#### 4.2 ArgoCD AppProject 配置

### 练习 1: 使用 Kustomize 创建多环境配置

**目标:** 使用 Kustomize base/overlay 结构创建 dev/staging/production 配置。

```bash
# 步骤 1: 创建目录结构
mkdir -p k8s/base
mkdir -p k8s/overlays/{dev,staging,production}

# 步骤 2: 创建 base 配置
cat > k8s/base/kustomization.yaml << 'EOF'
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - deployment.yaml
  - service.yaml
commonLabels:
  app: myapp
EOF

cat > k8s/base/deployment.yaml << 'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  replicas: 1
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
        - name: myapp
          image: nginx:1.24
          ports:
            - containerPort: 80
EOF

cat > k8s/base/service.yaml << 'EOF'
apiVersion: v1
kind: Service
metadata:
  name: myapp
spec:
  ports:
    - port: 80
      targetPort: 80
EOF

# 步骤 3: 创建 DEV overlay
cat > k8s/overlays/dev/kustomization.yaml << 'EOF'
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - ../../base
namespace: dev
namePrefix: dev-
commonLabels:
  environment: dev
patches:
  - target:
      kind: Deployment
      name: myapp
    patch: |
      - op: replace
        path: /spec/replicas
        value: 1
EOF

# 步骤 4: 创建 PRODUCTION overlay
cat > k8s/overlays/production/kustomization.yaml << 'EOF'
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - ../../base
namespace: production
namePrefix: prod-
commonLabels:
  environment: production
patches:
  - target:
      kind: Deployment
      name: myapp
    patch: |
      - op: replace
        path: /spec/replicas
        value: 3
EOF

# 步骤 5: 构建并验证
kustomize build k8s/overlays/dev
kustomize build k8s/overlays/production

# 步骤 6: 部署
kubectl create namespace dev
kubectl apply -k k8s/overlays/dev
```

## 面试题精选

### 1. 如何设计多环境管理策略？

**参考答案：**

多环境管理策略包含：

1. **环境分层**：DEV（开发）→ STAGING（预发布）→ PRODUCTION（生产），每层逐步提升质量要求
2. **配置管理**：使用 Kustomize overlays 或 Helm values 文件管理环境差异
3. **部署策略**：DEV 自动部署，STAGING 自动部署，PRODUCTION 手动审批
4. **Secret 管理**：使用 Sealed Secrets 或 External Secrets Operator
5. **GitOps**：配置存储在 Git 中，ArgoCD 自动同步

### 2. Kustomize 和 Helm 如何选择？

**参考答案：**

| 维度 | Kustomize | Helm |
|------|-----------|------|
| 复杂度 | 简单 | 复杂 |
| 模板语言 | 无（patch 机制） | Go Template |
| 依赖管理 | 无 | Chart 依赖 |
| 生态 | K8s 原生 | 丰富 |
| 适合场景 | 简单覆盖 | 复杂应用 |

选择依据：
- 简单覆盖用 Kustomize（base + overlay）
- 复杂应用用 Helm（模板 + 依赖）
- 可以组合使用（Kustomize 渲染 Helm Chart）

### 3. 如何实现 GitOps 多环境管理？

**参考答案：**

推荐方案：单分支 + 目录分离 + ArgoCD ApplicationSet

1. 一个 Git 仓库，main 分支
2. 目录结构：apps/myapp/overlays/{dev,staging,production}
3. ArgoCD ApplicationSet 自动为每个环境创建 Application
4. DEV/STAGING 自动同步，PRODUCTION 手动审批
5. 使用 RollingSync 策略控制同步顺序

### 4. 如何安全管理多环境的 Secret？

**参考答案：**

三种方案：

1. **Sealed Secrets**：加密后的 Secret 可以安全提交到 Git，集群内 Controller 自动解密
2. **External Secrets Operator**：从外部密钥管理服务（AWS Secrets Manager、Vault）同步 Secret
3. **Vault Agent Injector**：Sidecar 模式注入 Secret

选择：小团队用 Sealed Secrets，企业用 External Secrets + Vault。

### 5. ArgoCD 的 Sync Windows 有什么作用？

**参考答案：**

Sync Windows 限制自动同步的时间窗口：

- **allow 窗口**：允许自动同步的时间段
- **deny 窗口**：禁止自动同步的时间段

使用场景：
- 工作时间允许同步：`0 8-18 * * 1-5`
- 周末禁止同步：`0 0 * * 0,6`
- 维护窗口禁止同步

配合 manualSync: true，可以在允许窗口内手动触发同步。

### 6. 如何实现环境间的审批门控？

**参考答案：**

审批门控实现方式：

1. **Git PR Review**：STAGING → PRODUCTION 需要 PR 审批
2. **ArgoCD 手动同步**：PRODUCTION 环境不配置自动同步
3. **CI/CD 审批步骤**：在流水线中添加人工审批节点
4. **Sync Windows**：限制生产环境只能在工作时间同步

推荐组合：Git PR Review + ArgoCD 手动同步。

### 7. External Secrets Operator 和 Sealed Secrets 有什么区别？

**参考答案：**

| 特性 | Sealed Secrets | External Secrets |
|------|----------------|------------------|
| 存储位置 | Git (加密) | 外部密钥管理服务 |
| 密钥管理 | Controller 生成 | 外部服务管理 |
| 轮换 | 手动 | 自动 |
| 多集群 | 每集群独立 | 共享密钥服务 |
| 适合规模 | 小团队 | 大型企业 |

### 8. 如何处理多环境的数据库配置差异？

**参考答案：**

处理方式：

1. **ConfigMap/Secret**：每个环境独立的数据库连接信息
2. **环境变量**：通过 Kustomize/Helm 覆盖环境变量
3. **服务发现**：使用 K8s Service DNS 名（如 db.dev.svc.cluster.local）
4. **配置中心**：使用 Nacos/Apollo 等配置中心管理

最佳实践：数据库连接信息使用 Secret，通过 Kustomize overlay 或 Helm values 区分环境。

### 9. 如何实现跨环境的配置一致性？

**参考答案：**

配置一致性保证：

1. **Base 共享**：使用 Kustomize base 定义通用配置
2. **模板复用**：使用 Helm templates 复用模板
3. **Git 单一事实源**：所有环境配置在同一个 Git 仓库
4. **ArgoCD 同步**：自动同步确保 Git 状态与集群一致
5. **配置校验**：CI 中验证配置语法和 schema

### 10. 如何处理多环境的网络隔离？

**参考答案：**

网络隔离方案：

1. **独立集群**：每个环境使用独立的 K8s 集群
2. **独立命名空间**：同集群不同命名空间 + NetworkPolicy
3. **服务网格**：使用 Istio 实现细粒度流量控制
4. **VPN/专线**：生产环境使用专线连接

推荐：生产环境独立集群，开发/测试可以共享集群但使用独立命名空间 + NetworkPolicy。
