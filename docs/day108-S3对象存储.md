### 1. S3 核心概念

S3（Simple Storage Service）是 AWS 的对象存储服务，提供 99.999999999%（11 个 9）的持久性。

```
┌─────────────────────────────────────────────────────────────────┐
│                    S3 架构                                       │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  Bucket（存储桶）                                         │   │
│  │  - 全局唯一名称                                           │   │
│  │  - 区域特定（数据存储在指定 Region）                      │   │
│  │  - 无数量限制                                             │   │
│  │                                                          │   │
│  │  ┌─────────────────────────────────────────────────────┐ │   │
│  │  │  Object（对象）                                       │ │   │
│  │  │  - Key（键）：对象的唯一标识（类似文件路径）          │ │   │
│  │  │  - Body（内容）：实际数据（最大 5TB）                 │ │   │
│  │  │  - Metadata（元数据）：自定义键值对                   │ │   │
│  │  │  - Version ID（版本标识）：启用版本控制后每个对象     │ │   │
│  │  │  - Storage Class（存储类）：决定成本和访问性能        │ │   │
│  │  └─────────────────────────────────────────────────────┘ │   │
│  │                                                          │   │
│  │  Key 示例：                                               │   │
│  │  logs/2026/05/07/app-server-01.log                       │   │
│  │  ├── 前缀：logs/2026/05/07/                              │   │
│  │  └── 对象名：app-server-01.log                           │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  S3 vs 文件系统：                                                │
│  - 没有真正的"目录"概念，Key 中的 / 只是视觉分隔               │
│  - 不支持就地修改（需要重新上传整个对象）                       │
│  - 支持并发读取，但写入需要乐观锁（ETag/版本控制）             │
└─────────────────────────────────────────────────────────────────┘
```

```bash
# 创建 Bucket
aws s3 mb s3://sre-logs-2026-us-east-1 --region us-east-1

# 列出 Bucket
aws s3 ls

# 列出 Bucket 中的对象
aws s3 ls s3://sre-logs-2026-us-east-1/
aws s3 ls s3://sre-logs-2026-us-east-1/logs/ --recursive

# 上传文件
aws s3 cp ./app.log s3://sre-logs-2026-us-east-1/logs/2026/05/07/app.log

# 同步目录
aws s3 sync ./logs/ s3://sre-logs-2026-us-east-1/logs/ --exclude "*.tmp"

# 下载
aws s3 cp s3://sre-logs-2026-us-east-1/logs/2026/05/07/app.log ./downloaded.log

# 删除对象
aws s3 rm s3://sre-logs-2026-us-east-1/logs/2026/05/07/app.log

# 删除 Bucket（必须先清空）
aws s3 rb s3://sre-logs-2026-us-east-1 --force
```

```bash
# 上传时指定存储类

  --recursive \
  --storage-class GLACIER \
  --metadata-directive REPLACE

# 查看对象的存储类
aws s3api head-object \
  --bucket sre-logs \
  --key logs/2026/05/07/app.log \
  --query "StorageClass"

# S3 Intelligent-Tiering 配置
aws s3api put-bucket-intelligent-tiering-configuration \
  --bucket sre-logs \
  --id auto-tiering \
  --intelligent-tiering-configuration '{
    "Id": "auto-tiering",
    "Status": "Enabled",
    "Tierings": [
      {"AccessTier": "ARCHIVE_ACCESS", "Days": 90},
      {"AccessTier": "DEEP_ARCHIVE_ACCESS", "Days": 180}
    ]
  }'
```

### 3. 生命周期策略

生命周期策略自动管理对象的存储类转换和过期删除。

### 4. 版本控制

版本控制保留对象的所有版本，防止意外删除和覆盖。

```
┌─────────────────────────────────────────────────────────────────┐
│                    S3 版本控制                                   │
│                                                                 │
│  Key: app/config.json                                           │
│                                                                 │
│  Version 3 (当前)    ← DELETE 标记                              │
│  Version 2           ← 最新内容                                │
│  Version 1           ← 旧版本                                  │
│                                                                 │
│  操作效果：                                                      │
│  PUT config.json    → 创建新版本（Version 3）                   │
│  DELETE config.json → 创建 DELETE 标记（不删除实际对象）        │
│  GET config.json    → 获取最新版本（Version 2 或 DELETE 标记）  │
│  GET ?versionId=v1  → 获取指定版本                              │
│                                                                 │
│  删除保护：                                                      │
│  - 暂停版本控制后，新上传的对象不创建版本                       │
│  - 使用 MFA Delete 需要 MFA 码才能永久删除版本                 │
│  - 使用生命周期策略自动清理旧版本                               │
└─────────────────────────────────────────────────────────────────┘
```

```bash
# 启用版本控制
aws s3api put-bucket-versioning \
  --bucket sre-app-data \
  --versioning-configuration Status=Enabled

# 查看版本控制状态
aws s3api get-bucket-versioning --bucket sre-app-data

# 列出对象的所有版本
aws s3api list-object-versions \
  --bucket sre-app-data \
  --prefix config/app.json \
  --query "Versions[*].[VersionId,LastModified,Size,IsLatest]"

# 恢复到指定版本（通过复制旧版本）
aws s3api copy-object \
  --bucket sre-app-data \
  --copy-source sre-app-data/config/app.json?versionId=abc123 \
  --key config/app.json

# 删除指定版本（永久删除）
aws s3api delete-object \
  --bucket sre-app-data \
  --key config/app.json \
  --version-id abc123

# 启用 MFA Delete（需要 root 账户）
aws s3api put-bucket-versioning \
  --bucket sre-app-data \
  --versioning-configuration Status=Enabled,MFADelete=Enabled \
  --mfa "arn:aws:iam::123456789012:mfa/root-account 123456"
```

### 5. 跨区域复制（CRR）

跨区域复制自动将对象复制到另一个 Region，用于灾备和合规。

```
┌─────────────────────────────────────────────────────────────────┐
│                    跨区域复制 (CRR)                              │
│                                                                 │
│  us-east-1 (源)                    eu-west-1 (目标)             │
│  ┌─────────────────┐              ┌─────────────────┐          │
│  │ sre-app-data    │   异步复制   │ sre-app-data-dr │          │
│  │                 │ ────────────▶│                 │          │
│  │ 新对象/更新     │   (分钟级)   │ 自动接收副本    │          │
│  │ 版本删除        │              │                 │          │
│  └─────────────────┘              └─────────────────┘          │
│                                                                 │
│  前置条件：                                                      │
│  1. 源和目标 Bucket 都启用版本控制                              │
│  2. 创建 IAM Role 授权 S3 复制                                 │
│  3. 源 Bucket 配置复制规则                                      │
│                                                                 │
│  注意：                                                          │
│  - 默认只复制新增/更新的对象                                    │
│  - 可选复制删除标记                                              │
│  - 可选复制现有对象（S3 Batch Replication）                    │
│  - 跨账户复制需要目标 Bucket 授权                               │
└─────────────────────────────────────────────────────────────────┘
```

```bash
# 创建复制 IAM Role
cat > /tmp/s3-replication-trust.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": "s3.amazonaws.com"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
EOF

aws iam create-role \
  --role-name S3ReplicationRole \
  --assume-role-policy-document file:///tmp/s3-replication-trust.json

cat > /tmp/s3-replication-policy.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetReplicationConfiguration",
        "s3:ListBucket"
      ],
      "Resource": "arn:aws:s3:::sre-app-data"
    },
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObjectVersionForReplication",
        "s3:GetObjectVersionAcl",
        "s3:GetObjectVersionTagging"
      ],
      "Resource": "arn:aws:s3:::sre-app-data/*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "s3:ReplicateObject",
        "s3:ReplicateDelete",
        "s3:ReplicateTags"
      ],
      "Resource": "arn:aws:s3:::sre-app-data-dr/*"
    }
  ]
}
EOF

aws iam put-role-policy \
  --role-name S3ReplicationRole \
  --policy-name S3ReplicationPolicy \
  --policy-document file:///tmp/s3-replication-policy.json

# 配置复制规则
aws s3api put-bucket-replication \
  --bucket sre-app-data \
  --replication-configuration '{
    "Role": "arn:aws:iam::123456789012:role/S3ReplicationRole",
    "Rules": [
      {
        "ID": "ReplicateAll",
        "Status": "Enabled",
        "Priority": 1,
        "Filter": {},
        "Destination": {
          "Bucket": "arn:aws:s3:::sre-app-data-dr",
          "StorageClass": "STANDARD"
        },
        "DeleteMarkerReplication": {
          "Status": "Enabled"
        }
      }
    ]
  }'

# 查看复制配置
aws s3api get-bucket-replication --bucket sre-app-data
```

### 7. 预签名 URL

预签名 URL 允许临时访问私有对象，无需公开 Bucket。

```bash
# 生成预签名 URL（下载，有效期 1 小时）
aws s3 presign s3://sre-private-bucket/reports/daily-2026-05-07.pdf \
  --expires-in 3600

# 生成预签名 URL（上传）
aws s3 presign s3://sre-upload-bucket/uploads/user-file.pdf \
  --expires-in 3600

# 使用预签名 URL 上传
curl -X PUT \
  -T ./local-file.pdf \
  "$(aws s3 presign s3://sre-upload-bucket/uploads/user-file.pdf --expires-in 3600)"

# Python 生成预签名 URL
python3 << 'EOF'
import boto3
from botocore.config import Config

s3 = boto3.client('s3', config=Config(signature_version='s3v4'))

# 生成下载 URL
url = s3.generate_presigned_url(
    'get_object',
    Params={'Bucket': 'sre-private-bucket', 'Key': 'reports/daily.pdf'},
    ExpiresIn=3600
)
print(f"Download URL: {url}")

# 生成上传 URL
url = s3.generate_presigned_url(
    'put_object',
    Params={'Bucket': 'sre-upload-bucket', 'Key': 'uploads/file.pdf'},
    ExpiresIn=3600
)
print(f"Upload URL: {url}")
EOF
```

### 8. 事件通知

S3 事件通知可以触发 Lambda、SQS、SNS 等服务响应对象变化。

```
┌─────────────────────────────────────────────────────────────────┐
│                    S3 事件通知                                   │
│                                                                 │
│  ┌──────────┐    ┌──────────────────────────────────────┐      │
│  │ S3 Bucket│    │ 事件类型                              │      │
│  │          │    │ - s3:ObjectCreated:Put               │      │
│  │ 新对象   │───▶│ - s3:ObjectCreated:Post              │      │
│  │ 删除     │    │ - s3:ObjectCreated:CompleteMultipart │      │
│  │ 恢复     │    │ - s3:ObjectRemoved:Delete            │      │
│  │ 标记     │    │ - s3:ObjectRestore:Completed         │      │
│  └──────────┘    └──────────┬───────────────────────────┘      │
│                             │                                   │
│                    ┌────────┼────────┐                          │
│                    ▼        ▼        ▼                          │
│              ┌─────────┐ ┌─────┐ ┌─────┐                       │
│              │ Lambda  │ │ SQS │ │ SNS │                       │
│              │         │ │     │ │     │                       │
│              │ 处理    │ │ 队列 │ │ 通知 │                       │
│              │ 图片    │ │ 消息 │ │ 邮件 │                       │
│              └─────────┘ └─────┘ └─────┘                       │
│                                                                 │
│  过滤条件：                                                      │
│  - Prefix：对象键前缀                                           │
│  - Suffix：对象键后缀（.jpg, .log）                             │
└─────────────────────────────────────────────────────────────────┘
```

```bash
# 配置事件通知（触发 Lambda）
aws s3api put-bucket-notification-configuration \
  --bucket sre-upload-bucket \
  --notification-configuration '{
    "LambdaFunctionConfigurations": [
      {
        "Id": "ProcessUploadedImage",
        "LambdaFunctionArn": "arn:aws:lambda:us-east-1:123456789012:function:process-image",
        "Events": ["s3:ObjectCreated:Put"],
        "Filter": {
          "Key": {
            "FilterRules": [
              {"Name": "prefix", "Value": "uploads/images/"},
              {"Name": "suffix", "Value": ".jpg"}
            ]
          }
```

## 🎯 面试题精选

### 题目 1：S3 的持久性是多少？如何理解？

**答：** S3 Standard 提供 99.999999999%（11 个 9）的持久性。意味着如果你存储 1000 万个对象，平均每 10000 年才会丢失 1 个对象。这是通过跨 3 个以上可用区的冗余存储实现的。

### 题目 2：S3 如何保证一致性？

**答：** S3 提供强一致性（自 2020 年 12 月起）：
- PUT：写入后立即可读
- DELETE：删除后立即不可见
- LIST：立即反映最新状态
- 覆盖写入：立即读到新版本

### 题目 3：S3 存储类如何选择？

**答：**
- 频繁访问 → Standard
- 不常访问但需要即时取回 → Standard-IA
- 可重新生成的数据 → One Zone-IA
- 访问模式不确定 → Intelligent-Tiering
- 归档需要即时取回 → Glacier Instant
- 归档偶尔取回 → Glacier Flexible（分钟~小时）
- 长期保留 → Glacier Deep Archive（12~48 小时）

### 题目 4：预签名 URL 的安全注意事项？

**答：**
1. 设置合理的过期时间（不要太长）
2. 使用 HTTPS
3. 限制特定操作（GET 或 PUT）
4. 可以通过 Condition 限制 IP 范围
5. 预签名 URL 包含凭证，不要记录到日志

### 题目 5：S3 的 100 个 Bucket 限制如何解决？

**答：** 默认限制 100 个 Bucket/账户，可以申请提高到 1000+。更好的做法：
- 使用前缀而非 Bucket 分隔数据
- 使用 Bucket Policy 和 IAM 策略控制访问
- 使用 S3 Access Points 管理不同访问场景

### 题目 6：如何防止 S3 数据被意外删除？

**答：**
1. 启用版本控制（保留所有版本）
2. 启用 MFA Delete（需要 MFA 码才能永久删除）
3. 配置 Object Lock（WORM 模式，合规保留）
4. Bucket Policy 中 Deny s3:DeleteObject
5. 跨区域复制（异地备份）
6. 启用公共访问阻止

### 题目 7：S3 Transfer Acceleration 是什么？

**答：** 利用 CloudFront 的边缘网络加速长距离传输。适合跨大陆上传大文件。使用特殊的端点 `s3-accelerate.amazonaws.com`。按传输量额外收费。

### 题目 8：S3 Select 是什么？适用场景？

**答：** S3 Select 允许使用 SQL 语句查询 CSV/JSON/Parquet 文件中的数据，无需下载整个文件。适用场景：
- 大型日志文件的快速查询
- CSV 数据的简单分析
- 减少数据传输量和处理时间
