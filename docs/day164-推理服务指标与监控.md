## 📖 核心知识点

### 1. LLM 推理服务核心指标

#### 1.1 指标全景图

```
┌──────────────────────────────────────────────────────────────┐
│                    LLM 推理服务指标体系                        │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  用户体验指标 (User Experience)                         │ │
│  │                                                        │ │
│  │  TTFT (Time to First Token)                            │ │
│  │  ├─ 首个 token 的响应时间                               │ │
│  │  ├─ 包含排队时间 + Prefill 时间                         │ │
│  │  ├─ 目标: < 500ms (交互场景)                            │ │
│  │  └─ 影响: 用户感知的"响应速度"                           │ │
│  │                                                        │ │
│  │  TPS (Tokens Per Second)                               │ │
│  │  ├─ 每秒生成的 token 数量                               │ │
│  │  ├─ 反映 Decode 阶段的速度                              │ │
│  │  ├─ 目标: > 30 tokens/s (交互场景)                      │ │
│  │  └─ 影响: 用户感知的"输出流畅度"                         │ │
│  │                                                        │ │
│  │  E2E Latency (端到端延迟)                               │ │
│  │  ├─ 从请求发送到完整响应的总时间                          │ │
│  │  ├─ = TTFT + Decode 时间                                │ │
│  │  ├─ 与输出长度成正比                                    │ │
│  │  └─ 流式场景下用户不感知（因为 TTFT 决定体验）            │ │
│  └────────────────────────────────────────────────────────┘ │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  服务性能指标 (Service Performance)                      │ │
│  │                                                        │ │
│  │  QPS (Queries Per Second)                              │ │
│  │  ├─ 每秒处理的请求数                                    │ │
│  │  ├─ 反映服务整体吞吐能力                                │ │
│  │  └─ 与 batch size 和 GPU 数量相关                       │ │
│  │                                                        │ │
│  │  Throughput (吞吐量)                                    │ │
│  │  ├─ 每秒处理的 token 数 (输入 + 输出)                   │ │
│  │  ├─ = QPS × 平均 token 数                               │ │
│  │  └─ 最大化吞吐量是成本优化的关键                         │ │
│  │                                                        │ │
│  │  Queue Time (排队时间)                                  │ │
│  │  ├─ 请求在队列中等待的时间                               │ │
│  │  ├─ 反映服务负载状况                                    │ │
│  │  └─ 目标: < 100ms                                      │ │
│  └────────────────────────────────────────────────────────┘ │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  资源指标 (Resource Metrics)                            │ │
│  │                                                        │ │
│  │  GPU Utilization (GPU 利用率)                           │ │
│  │  ├─ GPU 计算单元的使用比例                               │ │
│  │  ├─ 目标: 70-90% (过高可能导致排队)                      │ │
│  │  └─ 过低说明资源浪费                                    │ │
│  │                                                        │ │
│  │  GPU Memory Usage (显存使用)                            │ │
│  │  ├─ 模型权重 + KV Cache + 激活值                        │ │
│  │  ├─ > 90% 有 OOM 风险                                  │ │
│  │  └─ KV Cache 是动态变化的                               │ │
│  │                                                        │ │
│  │  GPU Temperature (GPU 温度)                             │ │
│  │  ├─ 正常: < 80°C                                       │ │
│  │  ├─ 告警: > 85°C                                       │ │
│  │  └─ 过高会导致降频，影响性能                             │ │
│  │                                                        │ │
│  │  Power Draw (功耗)                                      │ │
│  │  ├─ 接近 TDP 说明满载                                   │ │
│  │  └─ 用于成本核算                                        │ │
│  └────────────────────────────────────────────────────────┘ │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  可靠性指标 (Reliability)                               │ │
│  │                                                        │ │
│  │  Error Rate (错误率)                                    │ │
│  │  ├─ 5xx 错误 / 总请求数                                 │ │
│  │  ├─ OOM 错误率                                         │ │
│  │  └─ 超时率                                             │ │
│  │                                                        │ │
│  │  Availability (可用性)                                  │ │
│  │  ├─ 健康检查通过率                                      │ │
│  │  └─ 目标: 99.9% (每月 43 分钟)                          │ │
│  └────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

#### 1.2 指标计算方法

```
┌──────────────────────────────────────────────────────────────┐
│                    TTFT 和 TPS 计算示意                        │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  时间轴:                                                      │
│  │                                                           │
│  │  t0          t1                    t2                     │
│  │  │           │                     │                      │
│  │  │◀─排队时间─▶│◀──── Prefill ─────▶│◀── Decode ──▶│       │
│  │  │           │                     │              │       │
│  │  请求到达     开始处理               首token输出    最后token │
│  │                                                           │
│  │  TTFT = t2 - t0 = 排队时间 + Prefill 时间                 │
│  │  TPS  = token_count / (t2 - t_last_token)                │
│  │  E2E  = t_last_token - t0                                │
│  │  E2E  = TTFT + (token_count / TPS)                       │
│                                                              │
│  示例:                                                        │
│  - 请求到达 → 排队 50ms → Prefill 200ms → 首 token 输出      │
│  - TTFT = 250ms                                              │
│  - 后续每秒生成 40 个 token                                    │
│  - TPS = 40 tokens/s                                         │
│  - 输出 200 个 token                                          │
│  - E2E = 250ms + (200 / 40) × 1000ms = 5250ms               │
└──────────────────────────────────────────────────────────────┘
```

```yaml
      # 请求排队过多

        expr: vllm:num_requests_waiting > 50

      # 请求失败率高
```

### 3. 队列监控与请求追踪

#### 3.1 请求生命周期追踪

```
┌──────────────────────────────────────────────────────────────┐
│                    请求生命周期追踪                            │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  Client                                                     │
│    │                                                        │
│    │  1. 发送请求 (携带 X-Request-ID)                        │
│    ▼                                                        │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  API Gateway                                           │ │
│  │  ├─ 记录请求到达时间                                    │ │
│  │  ├─ 生成 X-Request-ID (如未提供)                        │ │
│  │  └─ 转发到后端                                          │ │
│  └───────────────────────┬────────────────────────────────┘ │
│                          │                                    │
│                          ▼                                    │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  vLLM 请求队列                                         │ │
│  │  ├─ 2. 请求进入队列 (记录 queue_enter_time)             │ │
│  │  ├─ 3. 调度器选择请求 (记录 queue_leave_time)           │ │
│  │  └─ queue_time = queue_leave - queue_enter             │ │
│  └───────────────────────┬────────────────────────────────┘ │
│                          │                                    │
│                          ▼                                    │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  Prefill 阶段                                          │ │
│  │  ├─ 4. 处理所有输入 token                               │ │
│  │  ├─ 计算 KV Cache                                      │ │
│  │  └─ prefill_time = t_first_token - t_start_prefill     │ │
│  └───────────────────────┬────────────────────────────────┘ │
│                          │                                    │
│                          ▼                                    │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  Decode 阶段                                           │ │
│  │  ├─ 5. 逐 token 生成（流式返回）                        │ │
│  │  ├─ 每个 token 的生成时间                               │ │
│  │  └─ decode_time = t_last_token - t_first_token         │ │
│  └───────────────────────┬────────────────────────────────┘ │
│                          │                                    │
│                          ▼                                    │
│  Client 收到完整响应                                          │
│                                                              │
│  指标汇总:                                                    │
│  TTFT      = queue_time + prefill_time                       │
│  TPS       = token_count / decode_time                       │
│  E2E       = TTFT + decode_time                              │
│  效率      = decode_time / E2E (越高说明排队越少)             │
└──────────────────────────────────────────────────────────────┘
```

#### 3.2 请求追踪中间件

```python
# request_tracker.py - 请求追踪中间件
import time
import uuid
import logging
from fastapi import Request, Response
from starlette.middleware.base import BaseHTTPMiddleware
from prometheus_client import Histogram, Counter, Gauge

# 定义 Prometheus 指标
REQUEST_LATENCY = Histogram(
    'llm_request_latency_seconds',
    'End-to-end request latency',
    ['method', 'endpoint', 'status_code'],
    buckets=[0.1, 0.5, 1, 2, 5, 10, 30, 60, 120, 300],
)

REQUEST_COUNT = Counter(
    'llm_request_total',
    'Total requests',
    ['method', 'endpoint', 'status_code'],
)

QUEUE_SIZE = Gauge(
    'llm_queue_size',
    'Current queue size',
)

ACTIVE_REQUESTS = Gauge(
    'llm_active_requests',
    'Currently active requests',
)

logger = logging.getLogger(__name__)

class RequestTrackerMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        # 生成或获取请求 ID
        request_id = request.headers.get("X-Request-ID", str(uuid.uuid4()))

        # 记录请求开始
        start_time = time.time()
        ACTIVE_REQUESTS.inc()

        logger.info(
            f"Request started: {request_id} "
            f"{request.method} {request.url.path}"
        )

        try:
            response = await call_next(request)

            # 记录请求完成
            elapsed = time.time() - start_time
            REQUEST_LATENCY.labels(
                method=request.method,
                endpoint=request.url.path,
                status_code=response.status_code,
            ).observe(elapsed)
            REQUEST_COUNT.labels(
                method=request.method,
                endpoint=request.url.path,
                status_code=response.status_code,
            ).inc()

            # 添加追踪头
            response.headers["X-Request-ID"] = request_id
            response.headers["X-Response-Time"] = f"{elapsed:.3f}s"

            logger.info(
                f"Request completed: {request_id} "
                f"status={response.status_code} "
                f"latency={elapsed:.3f}s"
            )

            return response

        except Exception as e:
            elapsed = time.time() - start_time
            REQUEST_LATENCY.labels(
                method=request.method,
                endpoint=request.url.path,
                status_code=500,
            ).observe(elapsed)
            REQUEST_COUNT.labels(
                method=request.method,
                endpoint=request.url.path,
                status_code=500,
            ).inc()

            logger.error(
                f"Request failed: {request_id} "
                f"error={str(e)} "
                f"latency={elapsed:.3f}s"
            )
            raise

        finally:
            ACTIVE_REQUESTS.dec()
```

```python
#!/usr/bin/env python3
"""cost_analyzer.py - LLM 推理成本分析工具"""

import json
import sys
from dataclasses import dataclass
from typing import Optional

@dataclass
class GPUSpec:
    name: str
    hourly_cost: float  # $/hour
    memory_gb: int
    tflops_fp16: float

@dataclass
class WorkloadSpec:
    daily_requests: int
    avg_input_tokens: int
    avg_output_tokens: int
    peak_qps: float
    availability_target: float  # 0.999 = 99.9%

# GPU 云上价格参考
GPU_PRICES = {
    "A100-80GB": GPUSpec("A100 80GB", 3.00, 80, 312),
    "H100-80GB": GPUSpec("H100 80GB", 4.50, 80, 990),
    "A10G-24GB": GPUSpec("A10G 24GB", 1.00, 24, 125),
    "L40S-48GB": GPUSpec("L40S 48GB", 2.00, 48, 366),
    "RTX-4090":  GPUSpec("RTX 4090 24GB", 0.50, 24, 165),
}

def estimate_monthly_tokens(workload: WorkloadSpec) -> dict:
    """估算月度 token 消耗"""
    daily_tokens = workload.daily_requests * (
        workload.avg_input_tokens + workload.avg_output_tokens
    )
    monthly_tokens = daily_tokens * 30
    return {
        "daily_input_tokens": workload.daily_requests * workload.avg_input_tokens,
        "daily_output_tokens": workload.daily_requests * workload.avg_output_tokens,
        "monthly_total_tokens": monthly_tokens,
        "monthly_total_millions": monthly_tokens / 1e6,
    }

def estimate_gpu_count(
    workload: WorkloadSpec,
    gpu: GPUSpec,
    tokens_per_second_per_gpu: float = 40,
    utilization_target: float = 0.7,
) -> int:
    """估算所需 GPU 数量"""
    daily_output_tokens = workload.daily_requests * workload.avg_output_tokens
    # 假设每天 12 小时高峰
    peak_hours = 12
    required_tps = daily_output_tokens / (peak_hours * 3600)
    # 考虑利用率目标
    required_tps_with_buffer = required_tps / utilization_target
    gpu_count = max(1, int(required_tps_with_buffer / tokens_per_second_per_gpu) + 1)
    # 高可用: 至少 2 个实例
    if workload.availability_target >= 0.999:
        gpu_count = max(2, gpu_count)
    return gpu_count

def calculate_monthly_cost(
    workload: WorkloadSpec,
    gpu_name: str = "A100-80GB",
    tokens_per_second_per_gpu: float = 40,
) -> dict:
    """计算月度成本"""
    gpu = GPU_PRICES[gpu_name]
    gpu_count = estimate_gpu_count(workload, gpu, tokens_per_second_per_gpu)
    monthly_hours = 730  # 平均每月小时数

    gpu_cost = gpu.hourly_cost * gpu_count * monthly_hours
    storage_cost = 50  # 模型存储 + 日志
    network_cost = 100  # 网络流量
    total_cost = gpu_cost + storage_cost + network_cost

    tokens = estimate_monthly_tokens(workload)
    cost_per_1k_tokens = (total_cost / tokens["monthly_total_millions"]) / 1000

    return {
        "gpu": gpu_name,
        "gpu_count": gpu_count,
        "monthly_gpu_cost": gpu_cost,
        "monthly_storage_cost": storage_cost,
        "monthly_network_cost": network_cost,
        "monthly_total_cost": total_cost,
        "monthly_tokens_millions": tokens["monthly_total_millions"],
        "cost_per_1k_tokens": round(cost_per_1k_tokens, 4),
        "cost_per_request": round(total_cost / (workload.daily_requests * 30), 4),
    }

def main():
    # 示例工作负载
    workload = WorkloadSpec(
        daily_requests=100000,
        avg_input_tokens=500,
        avg_output_tokens=200,
        peak_qps=50,
        availability_target=0.999,
    )

    print("=== LLM 推理成本分析 ===\n")
    print(f"工作负载:")
    print(f"  日请求量: {workload.daily_requests:,}")
    print(f"  平均输入: {workload.avg_input_tokens} tokens")
    print(f"  平均输出: {workload.avg_output_tokens} tokens")
    print(f"  峰值 QPS: {workload.peak_qps}")
    print()

    # 对比不同 GPU
    for gpu_name in GPU_PRICES:
        result = calculate_monthly_cost(workload, gpu_name)
        print(f"--- {gpu_name} ---")
        print(f"  GPU 数量: {result['gpu_count']}")
        print(f"  月度成本: ${result['monthly_total_cost']:,.0f}")
        print(f"  每 1K tokens: ${result['cost_per_1k_tokens']}")
        print(f"  每请求: ${result['cost_per_request']}")
        print()

if __name__ == "__main__":
    main()
```

```python
#!/usr/bin/env python3
"""llm_benchmark.py - LLM 推理性能基准测试工具"""

import asyncio
import aiohttp
import time
import json
import statistics
from dataclasses import dataclass, field
from typing import List

@dataclass
class BenchmarkResult:
    request_id: int
    ttft_ms: float = 0
    total_time_ms: float = 0
    token_count: int = 0
    tps: float = 0
    error: str = ""

@dataclass
class BenchmarkConfig:
    base_url: str = "http://localhost:8000"
    model: str = "meta-llama/Llama-3.1-8B-Instruct"
    prompt: str = "Explain the concept of Site Reliability Engineering in detail."
    max_tokens: int = 200
    concurrency_levels: List[int] = field(default_factory=lambda: [1, 2, 4, 8, 16, 32])
    requests_per_level: int = 10

async def single_request(
    session: aiohttp.ClientSession,
    config: BenchmarkConfig,
    request_id: int,
) -> BenchmarkResult:
    """发送单个流式请求并测量性能"""
    result = BenchmarkResult(request_id=request_id)
    payload = {
        "model": config.model,
        "messages": [{"role": "user", "content": config.prompt}],
        "max_tokens": config.max_tokens,
        "stream": True,
    }

    start = time.time()
    first_token_time = None

    try:
        async with session.post(
            f"{config.base_url}/v1/chat/completions",
            json=payload,
            timeout=aiohttp.ClientTimeout(total=300),
        ) as response:
            async for line in response.content:
                line = line.decode().strip()
                if line.startswith("data: "):
                    data = line[6:]
                    if data == "[DONE]":
                        break
                    try:
                        chunk = json.loads(data)
                        delta = chunk.get("choices", [{}])[0].get("delta", {})
                        if delta.get("content"):
                            if first_token_time is None:
                                first_token_time = time.time()
                            result.token_count += 1
                    except json.JSONDecodeError:
                        pass

        end = time.time()
        result.total_time_ms = (end - start) * 1000

        if first_token_time:
            result.ttft_ms = (first_token_time - start) * 1000
            decode_time = end - first_token_time
            if decode_time > 0:
                result.tps = result.token_count / decode_time

    except Exception as e:
        result.error = str(e)
        result.total_time_ms = (time.time() - start) * 1000

    return result

async def run_concurrent_benchmark(
    config: BenchmarkConfig,
    concurrency: int,
) -> List[BenchmarkResult]:
    """运行并发基准测试"""
    print(f"  并发数: {concurrency}, 请求数: {config.requests_per_level}")

    async with aiohttp.ClientSession() as session:
        tasks = [
            single_request(session, config, i)
            for i in range(config.requests_per_level)
        ]
        # 限制并发数
        semaphore = asyncio.Semaphore(concurrency)

        async def limited_request(task):
            async with semaphore:
                return await task

        results = await asyncio.gather(
            *[limited_request(t) for t in tasks],
            return_exceptions=True,
        )

    return [r for r in results if isinstance(r, BenchmarkResult)]

def print_results(concurrency: int, results: List[BenchmarkResult]):
    """打印测试结果"""
    successful = [r for r in results if not r.error]
    failed = [r for r in results if r.error]

    if not successful:
        print(f"  所有请求失败!")
        return

    ttfts = [r.ttft_ms for r in successful]
    tps_list = [r.tps for r in successful if r.tps > 0]
    total_times = [r.total_time_ms for r in successful]

    print(f"  成功: {len(successful)}/{len(results)}")
    print(f"  TTFT  - Avg: {statistics.mean(ttfts):.0f}ms, "
          f"P50: {statistics.median(ttfts):.0f}ms, "
          f"P95: {sorted(ttfts)[int(len(ttfts)*0.95)]:.0f}ms")
    if tps_list:
        print(f"  TPS   - Avg: {statistics.mean(tps_list):.1f}, "
              f"Min: {min(tps_list):.1f}, "
              f"Max: {max(tps_list):.1f}")
    print(f"  E2E   - Avg: {statistics.mean(total_times):.0f}ms, "
          f"P50: {statistics.median(total_times):.0f}ms")
    if failed:
        print(f"  失败: {len(failed)}")

async def main():
    config = BenchmarkConfig()

    print("=== LLM 推理性能基准测试 ===")
    print(f"模型: {config.model}")
    print(f"URL: {config.base_url}")
    print()

    for concurrency in config.concurrency_levels:
        results = await run_concurrent_benchmark(config, concurrency)
        print_results(concurrency, results)
        print()

if __name__ == "__main__":
    asyncio.run(main())
```

## 🎯 面试题精选

### 1. 什么是 TTFT 和 TPS？为什么它们是 LLM 服务最重要的指标？

**参考答案**：
- **TTFT（Time to First Token）**：从请求发出到收到第一个 token 的时间，包含排队时间和 Prefill 时间。
- **TPS（Tokens Per Second）**：每秒生成的 token 数量，反映 Decode 阶段的速度。

为什么最重要：
- TTFT 直接决定用户感知的"响应速度"。TTFT < 500ms 时用户感觉"即时响应"，> 2s 时感觉"卡顿"。
- TPS 决定输出的"流畅度"。TPS > 30 时用户感觉"流畅阅读"，< 10 时感觉"逐字蹦出"。
- 传统 Web 服务关注 QPS 和 P99 延迟，但 LLM 服务的延迟与输出长度成正比，所以需要 TTFT 和 TPS 这两个更精确的指标。

### 2. 如何设计 LLM 推理服务的 SLI/SLO？

**参考答案**：
SLI（Service Level Indicators）：
- TTFT P95 < 1s（交互场景）/ < 5s（批处理场景）
- TPS P50 > 30 tokens/s
- 请求成功率 > 99.5%
- 服务可用性 > 99.9%

SLO（Service Level Objectives）：
- 月度错误预算：0.1% 请求可以失败
- 月度延迟预算：5% 请求可以超过 TTFT 目标
- 月度可用性预算：43 分钟不可用

错误预算策略：
- 预算充足：正常迭代
- 预算紧张：冻结新功能，专注稳定性
- 预算耗尽：停止发布，全力修复

### 3. GPU 利用率低但用户反馈延迟高，如何排查？

**参考答案**：
这个矛盾通常说明瓶颈不在计算，而在其他环节：

1. **检查排队情况**：`vllm:num_requests_waiting` 是否很高？可能是调度问题。
2. **检查显存带宽**：Decode 阶段受显存带宽限制，不是计算限制。用 `DCGM_FI_DEV_MEM_COPY_UTIL` 检查。
3. **检查输入长度**：长输入的 Prefill 阶段计算密集，但 GPU 利用率统计可能不准确。
4. **检查 batch size**：并发数太低导致 GPU 利用率低，但单请求延迟不受影响。
5. **检查 PCIe/NVLink**：多卡通信瓶颈可能导致 GPU 空闲等待。
6. **检查 CPU 瓶颈**：tokenization、detokenization 等 CPU 操作可能是瓶颈。

### 4. 如何降低 LLM 推理成本？

**参考答案**：
1. **使用量化模型**：INT4 量化可将显存需求降低 4 倍，允许使用更少/更便宜的 GPU。
2. **优化批处理**：使用 Continuous Batching 提高 GPU 利用率。
3. **合理设置上下文长度**：限制 max_model_len，减少 KV Cache 显存占用。
4. **使用 Spot/抢占实例**：非关键服务可以使用 Spot GPU 实例，成本降低 60-70%。
5. **自动扩缩容**：低谷期缩容，高峰期扩容。
6. **模型选择**：小模型能满足需求就不必用大模型（8B vs 70B 成本差 10 倍）。
7. **缓存**：对相同/相似请求使用 KV Cache 复用或语义缓存。
8. **混合部署**：延迟不敏感的请求用批处理，延迟敏感的用在线服务。

### 5. 如何设置 LLM 服务的告警规则？

**参考答案**：
分级告警策略：

**P0（立即响应）**：
- 服务不可用（health check 失败）
- GPU 掉卡（ECC 不可修复错误）
- 请求错误率 > 10%

**P1（15 分钟内响应）**：
- TTFT P95 > 5s（超过 SLO）
- 请求排队 > 100
- GPU 温度 > 90°C
- 显存使用 > 95%

**P2（1 小时内响应）**：
- TTFT P95 > 2s（接近 SLO）
- GPU 利用率持续 > 95%（需要扩容）
- TPS 低于预期

**P3（工作日内处理）**：
- GPU 利用率持续 < 20%（资源浪费）
- 成本超出预算
