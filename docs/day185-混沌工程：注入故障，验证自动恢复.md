## 📖 详细知识点

### 1. 混沌工程原则

```
混沌工程 ≠ 随机破坏

原则：
1. 定义稳态假设（系统正常运行时的行为）
2. 覆盖真实世界事件（不是随机故障）
3. 在生产环境运行（但控制爆炸半径）
4. 持续自动化（不是手动操作）
5. 最小化爆炸半径（从 staging 开始）

实验流程：
计划 → 审批 → 执行 → 观察 → 修复 → 复盘
```

### 3. 混沌实验类型

#### 3.1 Pod Chaos

```yaml
# Pod Kill — 随机杀 Pod
apiVersion: chaos-mesh.org/v1alpha1
kind: PodChaos
metadata:
  name: pod-kill
  namespace: production
spec:
  action: pod-kill
  mode: one          # one: 杀 1 个, all: 杀全部, fixed: 杀 N 个
  selector:
    labelSelectors:
      app: web-app
  scheduler:
    cron: "@every 2m"   # 每 2 分钟执行一次
  duration: "30s"       # 实验持续 30 秒
```

#### 3.2 Network Chaos

```yaml
# 网络延迟
apiVersion: chaos-mesh.org/v1alpha1
kind: NetworkChaos
metadata:
  name: network-delay
  namespace: production
spec:
  action: delay
  mode: all
  selector:
    labelSelectors:
      app: api-service
  delay:
    latency: "200ms"
    correlation: "25"
    jitter: "50ms"
  duration: "60s"
```

#### 3.3 Stress Chaos

```yaml
# CPU 压力
apiVersion: chaos-mesh.org/v1alpha1
kind: StressChaos
metadata:
  name: cpu-stress
  namespace: production
spec:
  mode: one
  selector:
    labelSelectors:
      app: worker
  stressors:
    cpu:
      workers: 2       # 2 个 CPU worker
      load: 80         # 80% CPU 负载
  duration: "120s"
```

#### 3.4 IO Chaos

```yaml
# 磁盘 IO 延迟
apiVersion: chaos-mesh.org/v1alpha1
kind: IOChaos
metadata:
  name: io-delay
  namespace: production
spec:
  action: delay
  mode: all
  selector:
    labelSelectors:
      app: database
  delay: "100ms"
  path: "/var/lib/mysql"
  percent: 50          # 50% 的 IO 操作延迟
  duration: "60s"
```

### 4. 安全边界

```
爆炸半径控制：
┌─────────────────────────────────────┐
│  Stage 1: 开发环境                   │
│  → 全量实验，无风险                   │
├─────────────────────────────────────┤
│  Stage 2: Staging                   │
│  → 模拟生产配置，中等风险             │
├─────────────────────────────────────┤
│  Stage 3: 生产（单实例）              │
│  → mode: one，最小影响                │
├─────────────────────────────────────┤
│  Stage 4: 生产（多实例）              │
│  → mode: fixed(1)，可控影响           │
└─────────────────────────────────────┘

安全机制：
- TTL：实验自动过期（防止遗忘）
- 白名单：只允许对指定 Namespace 实验
- 审批流程：生产实验需人工审批
```

### 5. SRE 实战

```
实验：验证 HPA 自动扩缩容
前提：
  - web-app Deployment，minReplicas=2, maxReplicas=10
  - HPA 配置：CPU > 70% 扩容
  - 监控 Dashboard 已配置

步骤：
1. 创建 StressChaos：对 1 个 web-app Pod 注入 80% CPU 压力
2. 观察：
   - HPA 检测到 CPU 上升
   - 自动创建新 Pod
   - 总副本数从 2 增加到 N
3. 停止实验：
   - CPU 压力消失
   - HPA 缩容回 2 个 Pod
4. 验证：
   - 扩缩容时间 < 2 分钟
   - 服务无中断（HTTP 200 率 > 99.9%）
```
