# LLM SRE 22：前沿主题

本章用于跟踪仍在快速演进、尚未形成稳定平台定式的主题。这里所说的“前沿”，指的是它们已经开始影响容量、延迟、成本、治理或运行模式，但最佳实践、工具链和平台边界仍在变化中。

因此，本章不是核心入门材料，也不负责重复解释前面章节已经展开的基础运行机制。推理架构、性能、可观测性、可靠性、RAG/Agent 运行面和治理控制，分别以前文对应章节为主；本章更适合作为周期性跟踪清单，用来判断哪些新方向值得持续观察、试点或预研。

## MoE serving

主题标签：混合专家推理服务

### 这是什么

MoE serving 指混合专家模型在线推理的服务形态。请求经过路由器（router）后，只激活部分专家（expert），而不是每次都走完整稠密模型。

### 为什么重要

它让模型参数规模继续扩大，同时把单次推理的有效计算量控制在可接受范围内，因此常被用于高性能或高性价比模型。

### 对 SRE / 平台工程的影响

MoE 不只是“更大的模型”。平台上会新增 router 热点、expert 负载倾斜、跨节点 all-to-all 通信和容量规划复杂度。单看平均 GPU 利用率往往会掩盖热点 expert 导致的尾延迟。

### 应该观察哪些指标和信号

重点看 expert 命中分布、router 负载倾斜、跨节点通信时延、TTFT/TPOT 分位数、单 expert OOM 与热点重试比例。

### 适用边界

适合有成熟并行和网络基础设施的团队。不适合控制面薄弱、节点网络不稳定或排障能力不足的环境。

## ultra-long context

主题标签：超长上下文

### 这是什么

ultra-long context 指可处理极长上下文窗口的推理能力，通常达到数十万甚至百万 token。

### 为什么重要

它能减少外部检索和多轮拼接，把更多原始材料直接放进一次推理里，适合长文档分析、代码仓库问答和复杂会话。

### 对 SRE / 平台工程的影响

长上下文会显著放大预填充阶段（Prefill）成本、KV 缓存（KV Cache）占用、排队时间和请求差异性。资源管理会从“每请求是否成功”变成“长请求是否拖垮整池”。很多现有扩容、限流和配额模型在这里都会失效。

### 应该观察哪些指标和信号

重点看输入 token 分布、Prefill 延迟、KV Cache 水位、长请求拒绝率、上下文截断率、按上下文长度分桶的 TTFT/成本。

### 适用边界

适合确实需要原始长材料直接推理的场景。不适合把本应由检索、摘要或流程拆解解决的问题，一股脑转成超长上下文。

## prefill-decode disaggregation

主题标签：预填充与解码解耦

### 这是什么

prefill-decode disaggregation 指把预填充（Prefill）和解码（Decode）两个阶段拆到不同资源池或不同实例上执行，而不是由同一实例完整处理。

### 为什么重要

Prefill 计算重、Decode 时长长，两者对硬件和调度的需求不同。拆开后可以更细粒度地优化吞吐、成本和资源匹配。

### 对 SRE / 平台工程的影响

平台需要维护阶段间状态传递、调度一致性和失败恢复。观测面也要拆分，否则 TTFT 变慢时看不出问题落在 Prefill 池、Decode 池还是中间状态交换。

### 应该观察哪些指标和信号

重点看 Prefill 队列、Decode 队列、阶段切换耗时、状态传输失败率、分阶段 GPU 利用率、端到端 TTFT/TPOT。

### 适用边界

适合大规模推理平台和异构资源池。不适合实例数少、控制面简单或还没有稳定分阶段指标的环境。

## SGLang / structured generation runtime

主题标签：结构化生成运行时

### 这是什么

这里指以结构化生成、受约束解码和程序化推理编排为重点的运行时，例如 SGLang 一类结构化生成运行时（structured generation runtime）系统。

### 为什么重要

这类运行时能够让模型更稳定地产出 JSON、DSL、函数调用参数或多步骤推理结果，对 agent、工作流和平台集成很关键。

### 对 SRE / 平台工程的影响

运行时层会引入新的调度、缓存和约束解码路径。故障不再只表现为“模型慢或报错”，还可能表现为结构化输出失真、schema 不匹配或运行时状态机卡住。

### 应该观察哪些指标和信号

重点看结构化输出成功率、schema 校验失败率、约束解码回退率、运行时缓存命中率、单步骤耗时和异常终止率。

### 适用边界

适合需要稳定结构化输出和多步编排的场景。不适合只做简单聊天且不需要额外运行时复杂度的接口。

## FP8 / INT4

主题标签：低精度推理

### 这是什么

FP8 和 INT4 指更激进的低精度推理表示方式，用于降低显存占用、提升吞吐或扩大可部署模型规模。

### 为什么重要

低精度通常直接影响成本密度。相同 GPU 下，量化后可能跑更大模型、更多副本或更高并发。

### 对 SRE / 平台工程的影响

量化不是单纯的“更省资源”，它会引入精度回归、校准流程、硬件兼容性差异和更复杂的发布验证。平台必须把质量验证与容量优化一起做，而不是只看吞吐提升。

### 应该观察哪些指标和信号

重点看量化前后 TTFT/TPOT、显存占用、OOM 率、输出质量回归、回退比例、按模型版本分组的投诉与评测结果。

### 适用边界

适合成本敏感或显存受限场景。不适合高风险任务在未充分评测前直接全量切换。

## inference cache hierarchy

主题标签：推理缓存分层

### 这是什么

inference cache hierarchy 指推理链路中的多层缓存体系，例如权重缓存、前缀缓存（Prefix Cache）、KV 缓存（KV Cache）、工具结果缓存（tool result cache）和检索结果缓存。

### 为什么重要

缓存命中直接影响 TTFT、吞吐和成本。很多推理优化收益并不是来自模型更快，而是来自避免重复计算和重复 IO。

### 对 SRE / 平台工程的影响

多层缓存会增加一致性、驱逐和跨地域同步复杂度。缓存命中率下降常常先于整体性能退化出现，因此缓存本身就是一级运行对象，而不是附属指标。

### 应该观察哪些指标和信号

重点看各层命中率、驱逐率、失效率、缓存占用、跨副本复用收益、命中下降与 TTFT 恶化的相关性。

### 适用边界

适合重复前缀多、热点明显或工具结果可复用的业务。不适合数据高度随机、强一致性要求极高且缓存难以安全失效的场景。

## agent runtime

主题标签：智能体运行时

### 这是什么

agent runtime 指把模型、工具、状态、计划和执行流程组织成一个可持续运行系统的运行时层，也就是智能体运行时。

### 为什么重要

它让模型从“回答问题”扩展到“完成任务”，也是企业 AI 平台走向自动化执行的关键一步。

### 对 SRE / 平台工程的影响

平台需要处理多步状态、工具依赖、重试、幂等、人工接管和审计。可靠性模型会更接近工作流引擎，而不再是单次 RPC 服务。

### 应该观察哪些指标和信号

重点看任务完成率、平均步骤数、工具超时率、人工接管率、会话状态（session state）大小、单任务成本和异常终止率。

### 适用边界

适合确实需要多步骤决策和外部执行的业务。不适合为了“更智能”把简单同步接口过度 agent 化。

## synthetic data / automated eval

主题标签：合成数据与自动评测

### 这是什么

synthetic data / automated eval 指用模型或程序自动生成测试样本、评测数据和回归检查，用于持续验证模型、Prompt、RAG 和 agent 变更，也就是合成数据与自动评测链路。

### 为什么重要

AI 系统很难只靠单元测试保护质量。自动评测能把发布验证从人工抽查扩展到持续回归检查，是平台化运营的基础。

### 对 SRE / 平台工程的影响

评测系统本身会成为控制面依赖。平台要处理样本版本、评测基线、误报漏报、成本预算和与发布流水线的集成。没有自动评测，很多质量事故只能在用户投诉后才被发现。

### 应该观察哪些指标和信号

重点看评测通过率、关键能力分项分数、回归告警数、样本覆盖率、评测时延、评测成本和人工复核偏差。

### 适用边界

适合经常变更模型、Prompt、检索或工具链路的团队。不适合把自动评测结果当成唯一真相而忽略真实用户反馈。

## model routing / small-large cascade

主题标签：模型路由与大小模型级联

### 这是什么

model routing / small-large cascade 指根据请求难度、租户等级、成本目标或风险等级，把流量路由到不同模型，必要时由小模型先尝试，再升级到大模型，也就是模型路由与大小模型级联策略。

### 为什么重要

它是控制成本和延迟的常见手段。不是所有请求都值得占用最贵的模型容量。

### 对 SRE / 平台工程的影响

路由层会变成关键控制面。平台需要解释为什么某个请求进了某个模型，评估误路由成本，并处理多模型回退、缓存割裂和容量联动问题。

### 应该观察哪些指标和信号

重点看各模型流量占比、升级率、误路由率、分层 TTFT/成本、fallback 比例、路由变更后的质量投诉和错误预算消耗。

### 适用边界

适合请求复杂度差异大、模型层级清晰且平台有较好评测能力的环境。不适合模型差异难以量化、路由策略不可解释或缺少回归验证的数据薄弱团队。
