# LLM SRE 31：事故处置手册

使用说明：本手册用于 oncall 直接执行。先判定影响范围，再执行止血动作；如需升级，按当班升级链路同步平台负责人、业务负责人和相关基础设施团队。

## GPU OOM

### 症状

- TTFT、错误率或请求拒绝数突然升高，实例日志出现 `CUDA out of memory`、KV Cache 分配失败或容器重启。

### 前置检查

- 确认影响范围：单实例、单模型池还是全局。
- 检查显存占用、KV Cache 水位、上下文长度分布、waiting requests 和最近发布记录。
- 确认是否有长上下文流量、RAG 拼接膨胀、热点 LoRA 切换或量化版本变更。

### 止血动作

- 先摘除反复 OOM 的实例，避免重启风暴。
- 立即下调最大上下文长度、最大输出长度或并发上限。
- 对长请求和低优先级租户执行限流，必要时切到更大显存池或备用模型池。
- 若由新版本触发，直接回滚到上一版权重、量化产物或推理参数。

### 根因定位

- 核对模型版本、量化配置、Paged Attention 或 KV Cache 参数是否变更。
- 对比 OOM 前后输入长度、输出长度、Prefix Cache 命中率和 batch 波动。
- 检查是否存在显存泄漏、碎片恶化、LoRA 热加载异常或请求准入失效。

### 后续改进

- 为上下文长度、并发和 KV Cache 建立硬阈值，不依赖业务自觉控制。
- 将 OOM 告警直接绑定降级动作和回滚开关。
- 把长请求与常规请求分池，降低相互放大效应。

### 升级条件

- 15 分钟内无法止血、影响高优先级租户，或需跨团队处理显存/调度/发布问题。

### 恢复判定

- OOM 停止出现，错误率回落，TTFT 与拒绝请求恢复到基线范围。

### 需保留证据

- 告警时间线、实例日志、显存/KV Cache 曲线、变更记录、受影响请求样本。

## 模型加载失败

### 症状

- 新实例长时间未通过 readiness，扩容无效，日志出现权重拉取失败、Tokenizer 不匹配、显存初始化失败或校验错误。

### 前置检查

- 确认是单节点、单可用区还是整批实例失败。
- 检查镜像版本、制品仓库状态、对象存储权限、磁盘空间和节点 GPU 健康。
- 核对最近是否变更了权重路径、量化产物、Tokenizer、驱动或 CUDA/NCCL 版本。

### 止血动作

- 暂停继续扩容，防止把故障放大到整池。
- 立即切回上一版稳定镜像和制品引用。
- 将流量切到现存健康实例、备用模型池或备用地域。
- 如果是节点问题，隔离异常节点并阻止调度器继续分配。

### 根因定位

- 验证权重文件完整性、签名、路径和权限是否一致。
- 检查模型权重、Tokenizer、推理引擎和量化产物是否属于同一发布单元。
- 查看节点级日志，确认是否为驱动、显存、水位、文件系统或网络拉取问题。

### 后续改进

- 将模型加载前置为发布门禁，要求离线完成镜像和制品兼容性校验。
- 为权重拉取、校验、显存预热和 readiness 分段打点。
- 保持上一版制品和热实例可用，避免发布后只能硬扛。

### 升级条件

- 整池扩容受阻超过 10 分钟，或需制品、存储、节点团队共同介入。

### 恢复判定

- 新实例可稳定通过 readiness，扩容恢复生效，流量不再依赖应急切流。

### 需保留证据

- 加载失败日志、制品引用、节点事件、镜像版本、对象存储/文件系统错误记录。

## TTFT 飙升

### 症状

- TTFT p95/p99 快速抬升，用户首包明显变慢；常伴随 queue time 上升、waiting requests 增加或冷启动堆积。

### 前置检查

- 先区分 TTFT 上升是由 queue time、Prefill 还是冷启动造成。
- 检查流量峰值、输入长度分布、Prefix Cache 命中率和扩容状态。
- 查看是否有新模型发布、路由切换、索引版本变更或 RAG 上下文膨胀。

### 止血动作

- 对非核心流量限流，优先保护高优先级接口。
- 强制扩容到已预热实例，必要时切流到备用模型池。
- 临时缩短上下文上限、关闭高开销 reranker 或缩小 top-k。
- 若根因来自新版本或新路由，立即回滚。

### 根因定位

- 对比 queue time、Prefill token 吞吐、冷启动时长和 Prefix Cache 命中率。
- 检查是否是长 prompt、检索内容膨胀、批处理参数变化或调度失衡。
- 复核自动伸缩是否因错误指标、慢 readiness 或配额限制而失效。

### 后续改进

- 保证所有核心告警同时展示 TTFT 和 queue time，避免误判。
- 建立流量峰值前的预热和容量保底策略。
- 为 RAG 请求单独监控上下文 token 数与拼接模板变更。

### 升级条件

- 连续两个观察窗口未恢复，或需业务侧做强限流、功能降级或跨地域切流。

### 恢复判定

- TTFT 和 queue time 回到目标区间，waiting requests 回落，用户侧首包恢复正常。

### 需保留证据

- TTFT/queue time 曲线、扩容事件、流量切换记录、请求长度分布、灰度/发布记录。

## tokens/s 下降

### 症状

- 实例或模型池 tokens/s 持续低于基线，常伴随 GPU 忙碌度下降、batch 变小或输出吞吐抖动。

### 前置检查

- 检查是全局下降、单模型下降还是单租户下降。
- 对比 GPU 利用率、batch size、running requests、waiting requests 和请求长度结构。
- 确认是否刚上线了新量化方案、Speculative Decoding、Prefix Cache 或多 LoRA 复用策略。

### 止血动作

- 将热点流量切回稳定模型池或关闭收益不稳定的优化开关。
- 暂时降低并发目标，避免系统在低效 batch 上空转。
- 对长输出或长上下文流量单独限流，优先恢复主池稳定吞吐。

### 根因定位

- 分离分析 Prefill 吞吐和 Decode 吞吐，确认瓶颈是否落在显存带宽、KV Cache、水位或调度。
- 检查 batch 是否被多模型、多 LoRA、碎片化流量或保守限流策略打散。
- 核对网络、CPU、tokenization 或日志写入是否成为隐藏瓶颈。

### 后续改进

- 固化每次性能优化的回滚条件，不让值班时临时猜测。
- 用流量回放持续校验 tokens/s 基线，不只看离线 benchmark。
- 建立按模型池和租户分层的吞吐容量线。

### 升级条件

- 吞吐下降持续超过 15 分钟，或需关闭核心优化开关、回退版本、调整租户配额。

### 恢复判定

- tokens/s、batch 质量和 GPU 忙碌度恢复到稳定基线，未再依赖临时限流维持。

### 需保留证据

- tokens/s 基线对比、batch 指标、优化开关状态、模型池路由记录、实例性能日志。

## NCCL hang

### 症状

- 多节点训练或推理扩展任务长时间卡住，GPU 利用率异常低或部分 rank 不前进，日志出现 NCCL timeout、collective 卡死或 rank 不一致。

### 前置检查

- 确认是单作业问题还是同一节点池的普遍问题。
- 检查最近驱动、CUDA、NCCL、OFED、容器镜像和交换机配置变更。
- 核对受影响作业的节点拓扑、网卡错误计数、Xid/ECC 和调度落点。

### 止血动作

- 先终止已确定无法恢复的作业，释放被占用 GPU。
- 将异常节点从调度池摘除，阻止新作业继续落入。
- 回退到上一套稳定的驱动/NCCL/镜像组合，必要时缩小训练规模或降级到单节点验证。

### 根因定位

- 对比正常作业和异常作业的节点组合、拓扑和环境变量。
- 检查交换机丢包、RoCE/InfiniBand 配置、PFC/ECN 和网卡硬错误。
- 核查是否为框架版本不兼容、容器缺依赖、rank 映射错误或 checkpoint 恢复后状态不一致。

### 后续改进

- 建立经过验证的 NCCL 版本矩阵和节点准入流程。
- 为多节点作业保留网络与集体通信基线压测结果。
- 将异常节点自动隔离和复检纳入日常运维流程。

### 升级条件

- 影响多作业或整节点池，或需网络、集群、驱动团队协同排障。

### 恢复判定

- 作业可重新初始化并持续推进，NCCL timeout 消失，异常节点已隔离或修复。

### 需保留证据

- 作业日志、rank/节点映射、交换机或网卡错误计数、节点事件、版本矩阵。

## 向量检索超时

### 症状

- RAG 请求端到端延迟升高，检索阶段出现 timeout、空召回激增或应用直接退化到无检索回答。

### 前置检查

- 确认超时落在 query embedding、向量检索、reranker 还是元数据过滤。
- 检查向量库 CPU/内存/磁盘水位、分片热点、索引构建任务和网络路径。
- 核对是否刚进行了索引发布、embedding 升级、过滤条件调整或离线重建。

### 止血动作

- 临时缩小 top-k、关闭 reranker 或降级到关键词检索/缓存回答。
- 暂停离线重建或批量导入，优先恢复在线查询。
- 将热点租户或热点索引切到备用分片、只读副本或备用地域。
- 若新索引发布后触发超时，立刻切回上一版索引。

### 根因定位

- 查看慢查询分布，确认是过滤条件、索引参数、冷热数据混放还是分片倾斜。
- 检查 embedding 请求是否堆积，是否被离线任务抢占资源。
- 核对索引版本、chunk 策略和元数据字段是否与在线查询模板一致。

### 后续改进

- 将离线构建与在线查询资源隔离，避免重建拖垮主链路。
- 为 query embedding、检索、reranker 分别设超时和熔断，不让单点拖死整条链路。
- 保留索引发布回滚开关和版本审计，缩短恢复时间。

### 升级条件

- 超时影响核心问答路径超过一个观察窗口，或需索引回滚、分片迁移、存储团队介入。

### 恢复判定

- 检索超时率回落，端到端延迟恢复，空召回和降级回答比例回到基线。

### 需保留证据

- 慢查询样本、索引版本、分片水位、离线任务记录、超时请求 tracing。

## 模型质量突然回退

### 症状

- 指标层面可能只有空响应率、截断率、工具失败率或人工差评升高；业务反馈表现为答案跑偏、引用缺失、工具误调用或风格异常。

### 前置检查

- 先确认影响范围：全量流量、灰度流量、特定租户还是特定任务链路。
- 核对最近变更：基础模型、LoRA、Prompt 模板、索引版本、reranker、工具 schema、策略引擎。
- 检查是否伴随 TTFT、错误率或回退模型比例变化，避免把性能退化误当成纯质量问题。

### 止血动作

- 立即停止灰度并切回上一版稳定模型、Prompt、索引或工具配置。
- 对高风险场景关闭自动工具调用或切到人工兜底路径。
- 对关键租户启用保守模板、固定检索策略或稳定备用模型。

### 根因定位

- 抽样比对新旧版本的请求、检索命中、最终上下文、工具调用摘要和输出差异。
- 检查是否存在 embedding/索引 版本不一致、Prompt 注入防护误伤、LoRA 绑定错误或路由误切。
- 核对评测集、线上样本和人工反馈，确认回退是系统性还是局部场景漂移。

### 后续改进

- 将质量守护指标纳入灰度准入，不只看延迟和错误率。
- 保留线上请求抽样、引用来源和工具摘要，方便快速回放。
- 为模型、Prompt、索引和工具配置建立联动发布与回滚机制。

### 升级条件

- 影响高风险业务场景、关键租户或需回退多个发布单元联合排查。

### 恢复判定

- 质量守护指标回到基线，人工抽样确认主要错误模式消失，灰度保持关闭或恢复稳定。

### 需保留证据

- 受影响请求样本、新旧输出对比、索引/Prompt/模型版本、工具调用摘要、人工反馈记录。
