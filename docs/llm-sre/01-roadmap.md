# LLM SRE 学习路线图

本路线图默认你已经具备 Linux、容器、Kubernetes、监控告警和基础云平台知识。目标不是成为模型研究员，而是建立“能把 LLM 服务稳定、可观测、可扩展、可控地跑起来”的工程能力。

## 必学

- LLM 生命周期总览：预训练、微调、推理三阶段的目标、成本结构与责任边界。
- GPU 与推理基础设施：显存、带宽、拓扑、驱动、CUDA、容器运行时、节点调度。
- 模型部署与服务框架：vLLM、TGI、SGLang 一类推理框架的启动参数、并发模型与资源约束。
- 关键指标体系：TTFT、TPOT、tokens/s、吞吐、队列长度、GPU 利用率、KV Cache 命中与占用。
- 可观测性与告警：日志、指标、Tracing 如何拼出“慢、错、贵、抖”的根因链路。
- 高可用与容量管理：预热、滚动升级、故障隔离、弹性扩缩、热点模型治理。
- RAG 与应用侧依赖：检索、Embedding、向量库、重排、上下文膨胀对延迟和成本的影响。
- 安全与合规：模型访问控制、Prompt 注入、敏感数据处理、审计留痕。

## 进阶

- 并行与分布式推理：TP、PP、EP、DP 的适用边界与性能代价。
- 微调与模型版本管理：LoRA/QLoRA、权重与 Adapter 制品管理、回滚策略。
- 长上下文与 KV Cache 优化：Paged Attention、Prefix Cache、Chunked Prefill、Disaggregated Serving。
- 多租户平台治理：配额、优先级、隔离、资源售卖与成本分摊。
- 混合部署策略：不同模型大小、不同 GPU 代际、在线/离线推理混部。
- 质量与运维联动：离线评测、在线 A/B、回归基线、故障注入与压测。

## 前沿追踪

- MoE 推理调度与专家负载倾斜治理。
- 推理编排新范式：Prefill/Decode 解耦、异构加速器、远端 KV Cache。
- Agent 基础设施：工具调用链路、长会话状态、记忆与外部系统依赖的可观测性。
- 成本优化新手段：更细粒度量化、投机解码、动态批处理、功耗感知调度。
- 安全新议题：模型越权、数据外泄、合成内容治理、供应链可信性。

## 建议学习节奏

- 第 1 周：完成生命周期、GPU 基础设施、推理部署、核心指标四块内容，建立全局图。
- 第 2 周：补齐监控告警、高可用、容量规划与 RAG 运维，把“能跑”推进到“能稳”。
- 第 3 周：进入微调、并行、成本优化与安全合规，把“单点知识”串成系统能力。
- 持续阶段：每周固定追踪 1 个推理框架发布、1 篇工程博客、1 个生产案例，避免知识停在某个版本快照。

学习时建议遵循“先指标、后机制；先故障场景、后参数细节”的顺序。能解释一个指标为什么变坏、坏在哪里、该看哪一层，通常比背更多名词更重要。
