# LLM SRE 30：生产就绪检查清单

## 适用场景

- [ ] 新模型首次进入生产环境，需确认训练、推理、RAG/Agent、治理和回滚路径都已具备最小运行条件。
- [ ] 既有模型发生大版本升级，包括基础模型、量化产物、LoRA、Prompt 模板、索引版本或路由策略变更。
- [ ] 新租户、新地域或新模型池上线前，需复核容量、权限、SLO、审计和交接材料是否齐备。
- [ ] 重大活动、流量峰值、监管审计或跨团队交接前，需执行一次全量生产就绪检查。

## 训练平台检查项

- [ ] GPU 节点、驱动、CUDA、NCCL、OFED 与训练框架版本在验证矩阵内，没有临时拼装环境。
- [ ] 调度器已标注 GPU 类型、拓扑、网卡布局和节点池边界，避免异构节点混排。
- [ ] 训练数据路径、权限和版本已冻结，训练样本来源可追溯，敏感数据清洗策略已执行。
- [ ] checkpoint 写入路径、保留周期、恢复演练记录和跨可用区可读性已验证。
- [ ] 训练关键指标已接入监控，包括 step time、samples/s、tokens/s、重启次数、checkpoint 时长和失败率。
- [ ] 多节点训练已验证 NCCL 初始化、all-reduce 性能和节点摘除后的恢复路径。
- [ ] 微调产物、量化产物、LoRA 和评测结果已进入制品仓库，具备签名、版本和回滚指针。
- [ ] 训练任务的配额、优先级、抢占策略和人工升级路径已明确，避免推理资源被挤占。

## 推理平台检查项

- [ ] 模型权重、Tokenizer、量化版本、推理引擎参数和运行镜像已绑定为同一发布单元。
- [ ] readiness、warmup 和冷启动时长已验证，扩容后不会长时间卡在模型加载阶段。
- [ ] TTFT、TPOT、queue time、tokens/s、错误率、waiting requests 和 batch 指标已按模型池暴露。
- [ ] KV Cache、Prefix Cache、显存占用和请求拒绝数已接入仪表盘，并设置容量水位告警。
- [ ] 上下文长度、最大输出长度、并发上限和限流阈值已按模型等级设定，不使用默认无限制配置。
- [ ] 回退模型、备用模型池和跨地域切流路径已可用，且质量和成本边界已确认。
- [ ] 热点模型、热点 LoRA 或高优先级租户已完成预热，不依赖事故中临时拉起实例。
- [ ] 发布后关键 SLO 已定义，至少包含可用性、TTFT、错误率和质量守护指标。

## RAG / Agent 平台检查项

- [ ] embedding 模型版本、chunk 策略、索引版本和检索模板已显式绑定，避免多版本混用。
- [ ] 索引构建、发布、回滚和增量同步状态可见，线上可快速确认当前生效版本。
- [ ] 向量检索、reranker、上下文拼接和工具调用均有独立延迟与错误指标，不折叠成单一 LLM 延迟。
- [ ] 最终上下文 token 数、空召回率、工具超时率、步骤数上限和 session state 大小已可观测。
- [ ] 工具调用默认 deny，仅开放 allowlist，参数校验、超时、并发上限和幂等要求已落地。
- [ ] 检索失败、工具失败、reranker 异常和会话状态膨胀时有明确降级路径，例如跳过重排、关闭工具或缩短上下文。
- [ ] 引用来源、索引版本、工具调用摘要和最终路由模型已记录到审计或追踪链路。
- [ ] 离线摄取任务不会与在线查询抢占同一资源池，索引重建不会拖垮线上检索。

## 灰度与回滚检查项

- [ ] 灰度范围已定义清楚，包括租户、地域、模型池、流量比例和观察窗口。
- [ ] 灰度准入指标已明确，至少覆盖 TTFT、错误率、回退率、空响应率和核心业务反馈。
- [ ] 新旧版本支持并行观测，能按 trace ID、模型版本、索引版本和 Prompt 版本对比。
- [ ] 回滚动作已文档化并做过演练，明确是回滚权重、LoRA、Prompt、索引还是路由策略。
- [ ] 回滚后缓存清理、会话兼容、Prefix Cache 失效和索引切换副作用已评估。
- [ ] 灰度期间扩容、自动伸缩和发布冻结策略已设定，避免多变量同时变化。
- [ ] 高风险变更已准备人工兜底路径，包括强制切到备用模型、关闭工具调用或只读模式。

## 安全与审计检查项

- [ ] 生产模型、索引、Prompt、LoRA、工具权限和日志访问都走统一身份与授权体系。
- [ ] API Key、服务账号和第三方凭证已纳入轮换计划，不存在共享长期密钥。
- [ ] 输入、检索内容、工具输出和日志链路均有脱敏或 PII 扫描策略，并验证未写入原始敏感数据。
- [ ] 多租户隔离已覆盖命名空间、缓存键、索引空间、配额和成本归因。
- [ ] 所有高风险操作都有审计记录，至少包含身份、租户、模型/索引版本、工具摘要和策略命中结果。
- [ ] Prompt 注入、越权工具调用和异常高成本请求的阻断或告警策略已启用。
- [ ] 制品仓库、对象存储和向量库访问边界已验证，非生产环境不能直接读取生产敏感资产。

## 演练与交接检查项

- [ ] 值班手册已覆盖 GPU OOM、模型加载失败、TTFT 飙升、tokens/s 下降、NCCL hang、向量检索超时和质量回退。
- [ ] 近一次故障演练包含告警触发、止血、回滚、证据保留和复盘产出，且记录仍有效。
- [ ] 大盘、告警、日志、Tracing、变更记录和发布系统入口已收敛到统一值班入口。
- [ ] oncall 轮值、升级路径、职责边界和跨团队联系人已更新，不依赖单点专家记忆。
- [ ] 发布窗口、冻结策略、错误预算消耗规则和升级审批路径已明确。
- [ ] 交接材料已包含当前模型池清单、容量余量、已知风险、降级开关和最近一次变更摘要。
